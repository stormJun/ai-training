# 一图看懂：JSON vs Lark的本质区别

```
════════════════════════════════════════════════════════════════════
                        核心问题：谁在写"代码"？
════════════════════════════════════════════════════════════════════

方案A：Coze/Dify（用JSON）
────────────────────────────────────────────────────────────────────

【用户看到的】

    ╔═══════════════════════════════════════╗
    ║  Coze工作流编辑器                      ║
    ╟───────────────────────────────────────╢
    ║                                       ║
    ║   [开始] 👆拖拽                        ║
    ║     ↓                                 ║
    ║   [LLM] 👆选择模型                     ║
    ║     ↓                                 ║
    ║   [条件] 👆填表单                      ║
    ║     ↓                                 ║
    ║   [API调用]                           ║
    ║                                       ║
    ║   [保存] 👆点击按钮                    ║
    ╚═══════════════════════════════════════╝

              ↓ 前端自动生成

【后端存储的】（用户永远看不到）

    {
      "nodes": [
        {"type": "llm", "config": {...}},
        {"type": "condition", "config": {...}}
      ],
      "edges": [...]
    }

✅ 不需要Lark解析器（用JSON.parse()即可）
✅ 用户不会写错语法（因为是拖拽生成）


════════════════════════════════════════════════════════════════════

方案B：量化交易/Terraform（用Lark DSL）
────────────────────────────────────────────────────────────────────

【用户看到的】（VS Code编辑器）

    ╔═══════════════════════════════════════╗
    ║ trading_strategy.dsl                  ║
    ╟───────────────────────────────────────╢
    ║ 1  STRATEGY "趋势突破" VERSION 2.1     ║
    ║ 2  CAPITAL $100000                    ║  ← 用户手写
    ║ 3  RISK_PER_TRADE 2%                  ║  ← 用户手写
    ║ 4                                     ║
    ║ 5  ENTRY_RULE "突破买入"               ║  ← 用户手写
    ║ 6    WHEN price > SMA(20)             ║  ← 用户手写
    ║ 7      AND volume > AVG * 1.5         ║  ← 用户手写
    ║ 8    THEN BUY AT market_price         ║  ← 用户手写
    ║ 9         SIZE = CAPITAL * 2%         ║  ← 用户手写
    ╚═══════════════════════════════════════╝

              ↓ 需要Lark解析验证

【Lark解析器工作】

    parser.parse(dsl_code)
      ↓
    ✅ 验证语法：WHEN拼写正确吗？
    ✅ 验证单位：$100000确实是美元吗？
    ✅ 验证类型：2%确实是百分比吗？
    ✅ 验证逻辑：SMA函数参数正确吗？
      ↓
    生成可执行代码

✅ 必须用Lark解析器（人类会写错）
✅ 需要领域特定语法（单位、类型检查）


════════════════════════════════════════════════════════════════════
                              对比总结
════════════════════════════════════════════════════════════════════

┌─────────────────┬──────────────────┬──────────────────┐
│   判断标准      │   Coze方案       │   Lark方案       │
├─────────────────┼──────────────────┼──────────────────┤
│ 输入方式        │ 🖱️ 拖拽界面      │ ⌨️ 写文本代码     │
├─────────────────┼──────────────────┼──────────────────┤
│ 谁在写"代码"    │ 前端JavaScript   │ 人类（技术人员） │
├─────────────────┼──────────────────┼──────────────────┤
│ 用户能力要求    │ 业务人员         │ 技术人员         │
├─────────────────┼──────────────────┼──────────────────┤
│ 学习成本        │ 5分钟上手        │ 需学DSL语法      │
├─────────────────┼──────────────────┼──────────────────┤
│ 需要解析器      │ ❌ 不需要        │ ✅ 必须          │
├─────────────────┼──────────────────┼──────────────────┤
│ 为什么          │ JSON自动生成     │ 人类会写错       │
├─────────────────┼──────────────────┼──────────────────┤
│ 典型应用        │ Coze, Dify, n8n  │ 交易策略, Nginx  │
└─────────────────┴──────────────────┴──────────────────┘


════════════════════════════════════════════════════════════════════
                           记忆口诀
════════════════════════════════════════════════════════════════════

🖱️ 拖拽生成 = JSON够了（Coze）
⌨️ 手写代码 = 需要Lark（交易策略）

关键不在于"能不能用JSON"，而在于"谁在写代码"！

════════════════════════════════════════════════════════════════════
```
