## 14. 策略优化算法

前面的基础篇已经讲过 Policy Gradient 和 Actor-Critic 的架构与更新直觉。本章在此基础上继续展开现代策略优化算法：

```text
Policy Gradient
-> Actor-Critic
-> Advantage / GAE
-> A2C / A3C / SAC
-> TRPO / PPO
-> DPG / DDPG / TD3
```

这一章的核心问题是：

> 策略模型到底怎么更新，才能既提高长期回报，又避免每次更新太激进导致训练崩掉？

这一章也是后面大模型相关章节的算法基础。尤其是 PPO、KL 约束、Advantage、Actor-Critic 这些概念，都会在第 21 章和第 22 章中反复出现。

### 14.1 Advantage、A2C/A3C、SAC 与 GAE

策略梯度里真正重要的不是“这个动作绝对回报有多高”，而是：

> 这个动作比当前状态下的平均水平好多少？

这就是优势函数。

#### 14.1.1 优势函数（Advantage）

优势函数定义为：

$$
A^\pi(s,a)
=
Q^\pi(s,a)
- V^\pi(s)
$$

直觉是：

```text
Qπ(s,a)：在状态 s 下做动作 a 的价值
Vπ(s)：状态 s 下按当前策略行动的平均水平
Aπ(s,a)：动作 a 比平均水平好多少
```

在策略梯度中，用 Advantage 替代原始回报：

$$
\nabla_\theta J(\theta)
=
\mathbb{E}
\left[
\nabla_\theta \log \pi_\theta(a_t \mid s_t)
A^\pi(s_t,a_t)
\right]
$$

这样可以降低方差。

如果 $A_t > 0$：

```text
这个动作比平均水平好 -> 增加它的概率
```

如果 $A_t < 0$：

```text
这个动作比平均水平差 -> 降低它的概率
```

常见 Advantage 估计方式包括：

```text
Monte Carlo: A_t = G_t - V(s_t)
TD Error:    A_t ≈ r_t + γV(s_{t+1}) - V(s_t)
GAE:         对多步 TD Error 做指数加权
```

#### 14.1.2 A2C 与 A3C：同步和异步的 Advantage Actor-Critic

**A2C（Advantage Actor-Critic）** 是同步版 Actor-Critic。

它通常并行跑多个环境，收集一批轨迹后统一更新：

```text
多个环境同步采样
-> 收集 n-step trajectory
-> 计算 Advantage
-> 更新 Actor 和 Critic
```

A2C 的典型损失由三部分组成：

$$
\mathcal{L}
=
\mathcal{L}_{policy}
+
c_v \mathcal{L}_{value}
-
c_e \mathcal{H}(\pi_\theta)
$$

其中：

$$
\mathcal{L}_{policy}
=
-
\log \pi_\theta(a_t \mid s_t)
A_t
$$

$$
\mathcal{L}_{value}
=
\frac{1}{2}
\left(
R_t^{target}
- V_w(s_t)
\right)^2
$$

$$
\mathcal{H}(\pi_\theta)
=
-
\sum_a
\pi_\theta(a \mid s_t)
\log \pi_\theta(a \mid s_t)
$$

熵项 $\mathcal{H}$ 用来鼓励探索，避免策略太早变成确定性。

**A3C（Asynchronous Advantage Actor-Critic）** 是异步版 Actor-Critic。

它让多个 worker 独立和环境交互，并异步更新全局参数：

```text
Worker 1 采样并更新全局模型
Worker 2 采样并更新全局模型
Worker 3 采样并更新全局模型
...
```

A3C 的优点是采样多样性强，早期深度 RL 中很常见；缺点是异步训练工程复杂度更高，现代实现中常用 A2C 或 PPO 替代。

#### 14.1.3 SAC：最大熵 Actor-Critic

**SAC（Soft Actor-Critic）** 是最大熵 Actor-Critic。

它不只最大化回报，还鼓励策略保持足够随机：

$$
J(\pi)
=
\mathbb{E}
\left[
\sum_t
r_t
+
\alpha
\mathcal{H}(\pi(\cdot \mid s_t))
\right]
$$

其中 $\alpha$ 是温度系数，控制“奖励”和“熵”的权衡。

SAC 的策略目标常写成：

$$
J_\pi(\theta)
=
\mathbb{E}_{s_t, a_t \sim \pi_\theta}
\left[
\alpha \log \pi_\theta(a_t \mid s_t)
- Q_w(s_t,a_t)
\right]
$$

Critic target 常见形式是：

$$
y_t =
r_t
+
\gamma
\left[
\min_{i=1,2} Q_{w_i^-}(s_{t+1}, a_{t+1})
- \alpha \log \pi_\theta(a_{t+1} \mid s_{t+1})
\right]
$$

SAC 适合连续动作控制，稳定性和样本效率通常都不错。

#### 14.1.4 GAE（广义优势估计）算法

GAE（Generalized Advantage Estimation）是 PPO、A2C 等算法里非常常见的 Advantage 估计方法。

先定义一步 TD Error：

$$
\delta_t
=
r_t
+
\gamma V(s_{t+1})
-
V(s_t)
$$

GAE 把未来多个 TD Error 做指数加权：

$$
\hat{A}_t^{GAE(\gamma,\lambda)}
=
\sum_{l=0}^{\infty}
(\gamma \lambda)^l
\delta_{t+l}
$$

如果 episode 是有限长度，实际代码中从后往前递推：

```text
gae = 0
for t from T-1 down to 0:
    delta = r_t + gamma * V(s_{t+1}) * (1 - done_t) - V(s_t)
    gae = delta + gamma * lambda * (1 - done_t) * gae
    advantage_t = gae
    return_t = advantage_t + V(s_t)
```

这里：

- `advantage_t` 用来更新 Actor
- `return_t` 用来训练 Critic

GAE 的作用是平衡偏差和方差：

```text
λ 小：更接近一步 TD，方差小但偏差大
λ 大：更接近 Monte Carlo，偏差小但方差大
```

#### 14.1.5 γ 和 λ 的调节作用

$\gamma$ 和 $\lambda$ 都会影响“未来信息传多远”，但含义不同。

| 参数 | 控制对象 | 越小 | 越大 |
|---|---|---|---|
| $\gamma$ | 未来奖励折扣 | 更短视，更重视即时奖励 | 更长远，更重视长期奖励 |
| $\lambda$ | Advantage 估计跨度 | 更像 TD(0)，方差低、偏差高 | 更像 MC，偏差低、方差高 |

可以这样理解：

```text
γ 决定任务目标本身有多看重未来
λ 决定训练时 Advantage 估计用多长的信用分配链条
```

常见经验值是：

```text
gamma = 0.99
lambda = 0.95
```

但这不是定律。短期任务可以用更小的 $\gamma$；奖励稀疏、长期依赖强的任务通常需要更大的 $\gamma$。

### 14.2 PPO 及其相关算法

PPO（Proximal Policy Optimization）是现代策略优化里最常用的算法之一。

它的核心目标是：

> 让策略朝更高回报方向更新，但每次更新不要偏离旧策略太远。

#### 14.2.1 PPO 算法的演进

可以按下面路线理解 PPO 的来历：

```text
Policy Gradient
-> 直接最大化期望回报，但更新可能过猛
-> TRPO
-> 用 KL 约束限制新旧策略距离
-> PPO
-> 用更简单的一阶优化近似 trust region
```

Policy Gradient 的问题是：一次梯度更新如果太大，新策略可能和旧策略差别很大，导致采样数据不再可靠，训练性能突然下降。

TRPO 和 PPO 都在解决这个问题：

```text
既要让策略变好
又要限制策略每次只变一点点
```

#### 14.2.2 TRPO（置信域策略优化）

TRPO（Trust Region Policy Optimization）把策略更新写成带约束优化：

$$
\max_\theta
\mathbb{E}
\left[
\frac{
\pi_\theta(a_t \mid s_t)
}{
\pi_{\theta_{old}}(a_t \mid s_t)
}
\hat{A}_t
\right]
$$

约束是新旧策略的 KL 距离不能太大：

$$
\mathbb{E}
\left[
D_{KL}
\left(
\pi_{\theta_{old}}(\cdot \mid s_t)
\parallel
\pi_\theta(\cdot \mid s_t)
\right)
\right]
\le
\delta
$$

这里的 **KL 散度（Kullback-Leibler Divergence）** 用来衡量两个概率分布有多不一样。

对于离散概率分布 $P$ 和 $Q$，KL 散度定义为：

$$
D_{KL}(P \parallel Q)
=
\sum_x
P(x)
\log
\frac{
P(x)
}{
Q(x)
}
$$

直觉上可以这样理解：

```text
KL 较小：两个概率分布接近
KL 较大：两个概率分布差异明显
```

需要注意，KL 散度并不是严格意义上的距离，因为它通常不对称：

$$
D_{KL}(P \parallel Q)
\ne
D_{KL}(Q \parallel P)
$$

在策略优化中，$P$ 和 $Q$ 通常分别对应旧策略与新策略。限制 KL 散度，就是限制新策略每次不要变化得太激进：

```text
旧策略：在当前状态下，各个动作原本有一组选择概率
新策略：参数更新后，各个动作有了新的选择概率

如果两组概率差异太大
-> 说明策略一步改得太多
-> 旧策略采集的数据可能不再可靠
-> 训练容易不稳定
```

例如：

```text
旧策略：[向左 0.50, 向右 0.50]
新策略：[向左 0.52, 向右 0.48]
-> KL 较小，更新较温和

旧策略：[向左 0.50, 向右 0.50]
新策略：[向左 0.99, 向右 0.01]
-> KL 较大，更新过于激进
```

其中：

- $\theta_{old}$：采样数据时的旧策略参数
- $\theta$：准备更新的新策略参数
- $\hat{A}_t$：优势估计
- $\delta$：允许的最大策略变化幅度

TRPO 的思想很清楚，但实现上通常需要二阶近似、共轭梯度等步骤，工程复杂度较高。

#### 14.2.3 重要性采样（Importance Sampling）

PPO 和 TRPO 都会用旧策略采样数据，再用这些数据更新新策略。

问题是：

```text
数据来自旧策略 π_old
但我们想优化新策略 πθ
```

重要性采样用概率比值修正这种差异：

$$
r_t(\theta)
=
\frac{
\pi_\theta(a_t \mid s_t)
}{
\pi_{\theta_{old}}(a_t \mid s_t)
}
$$

如果 $r_t(\theta) > 1$，说明新策略比旧策略更倾向于选择当时那个动作。

如果 $r_t(\theta) < 1$，说明新策略比旧策略更不倾向于选择当时那个动作。

基础替代目标可以写成：

$$
L^{PG}(\theta)
=
\mathbb{E}
\left[
r_t(\theta)
\hat{A}_t
\right]
$$

但如果 $r_t$ 变化太大，更新就会不稳定。PPO 的重点就是限制这个 ratio。

#### 14.2.4 PPO-Penalty

PPO-Penalty 直接把 KL 距离作为惩罚项加进目标函数：

$$
L^{KLPEN}(\theta)
=
\mathbb{E}
\left[
r_t(\theta)\hat{A}_t
-
\beta
D_{KL}
\left(
\pi_{\theta_{old}}(\cdot \mid s_t)
\parallel
\pi_\theta(\cdot \mid s_t)
\right)
\right]
$$

其中 $\beta$ 控制 KL 惩罚强度。

如果新旧策略差太远：

```text
KL 变大
-> 惩罚变大
-> 阻止策略继续大幅偏移
```

PPO-Penalty 的问题是 $\beta$ 需要调节。$\beta$ 太小约束不够，$\beta$ 太大更新太保守。

#### 14.2.5 PPO-Clip

PPO-Clip 是最常见的 PPO 形式。

它不用显式把 KL 加到目标里，而是直接裁剪 ratio：

$$
L^{CLIP}(\theta)
=
\mathbb{E}
\left[
\min
\left(
r_t(\theta)\hat{A}_t,
\operatorname{clip}
(r_t(\theta), 1-\epsilon, 1+\epsilon)
\hat{A}_t
\right)
\right]
$$

其中 $\epsilon$ 常见取值是 0.1 或 0.2。

可以分情况理解。

如果 $\hat{A}_t > 0$：

```text
这个动作比平均水平好
-> 希望提高它的概率
-> 但最多提高到 old_prob * (1 + ε)
```

如果 $\hat{A}_t < 0$：

```text
这个动作比平均水平差
-> 希望降低它的概率
-> 但最多降低到 old_prob * (1 - ε)
```

PPO-Clip 的核心不是阻止策略更新，而是阻止“已经更新得够多的样本”继续推动策略。

#### 14.2.6 PPO 的 Loss 的扩展

实际 PPO 通常同时训练 Actor 和 Critic，并加入熵奖励。

常见总损失写成最小化形式：

$$
\mathcal{L}_{PPO}
=
-
L^{CLIP}(\theta)
+
c_v
\mathcal{L}_{value}
-
c_e
\mathcal{H}(\pi_\theta)
$$

其中：

$$
\mathcal{L}_{value}
=
\frac{1}{2}
\left(
V_w(s_t)
-
R_t^{target}
\right)^2
$$

熵项：

$$
\mathcal{H}(\pi_\theta)
=
-
\sum_a
\pi_\theta(a \mid s_t)
\log \pi_\theta(a \mid s_t)
$$

三个部分分别负责：

| 部分 | 作用 |
|---|---|
| $L^{CLIP}$ | 更新策略，让高优势动作概率上升、低优势动作概率下降 |
| Value loss | 训练 Critic，让价值估计更准 |
| Entropy bonus | 鼓励探索，避免策略过早塌缩 |

在需要限制新策略不要偏离旧策略或参考策略太远的场景中，也可以加入 KL 约束：

$$
\mathcal{L}
=
\mathcal{L}_{PPO}
+
\beta
D_{KL}
(\pi_\theta \parallel \pi_{ref})
$$

这里的 $\pi_{ref}$ 表示参考策略，用来防止当前策略为了追求短期奖励而偏离原有行为分布太远。

#### 14.2.7 TRPO 与 PPO 的区别

| 对比项 | TRPO | PPO |
|---|---|---|
| 核心思想 | 显式 KL 约束 trust region | 用 penalty 或 clip 近似限制更新幅度 |
| 优化方式 | 约束优化，常涉及二阶方法 | 普通一阶梯度优化 |
| 实现复杂度 | 较高 | 较低 |
| 工程使用 | 相对少 | 非常常见 |
| 稳定性 | 理论约束更强 | 实践稳定且实现简单 |

一句话：

```text
TRPO：严格控制新旧策略 KL 距离
PPO：用更简单的 clip 或 penalty 达到类似效果
```

#### 14.2.8 图解策略模型的训练

PPO 的训练流程可以这样看：

```text
旧策略 π_old
  |
  | 采样 trajectories
  v
经验数据 (s, a, r, log_prob_old, value_old, done)
  |
  | 反向计算 return 和 GAE advantage
  v
训练 batch
  |
  | 当前策略 πθ 重新计算 log_prob_new 和 value_new
  v
ratio = exp(log_prob_new - log_prob_old)
  |
  v
PPO-Clip policy loss + value loss + entropy bonus
  |
  v
更新 Actor 和 Critic
  |
  v
同步：π_old ← πθ，进入下一轮采样
```

关键点是：PPO 不是每条数据只更新一次。通常会对同一批 rollout 数据做多个 epoch 的 mini-batch 更新，但 ratio 和 clip 会限制策略不要离采样时的旧策略太远。

#### 14.2.9 深入解析 PPO 的本质

PPO 的本质可以压缩成三句话：

```text
1. 用 Advantage 判断动作该被鼓励还是抑制
2. 用重要性采样 ratio 复用旧策略采样的数据
3. 用 clip / KL 限制新策略相对旧策略的变化幅度
```

它真正优化的不是单步 reward，而是“当前策略下动作概率的局部调整”：

- 好动作：概率提高一点
- 差动作：概率降低一点
- 已经提高或降低太多：停止继续推

因此 PPO 很适合神经网络策略训练：

```text
足够稳定
实现不太复杂
能复用一批 rollout 数据做多轮更新
适合离散动作、连续动作和神经网络策略
```

但 PPO 仍然是 on-policy 风格算法。数据来自旧策略，不能无限复用；如果复用太多轮，旧数据和新策略差距变大，训练会失真。

### 14.3 确定性策略梯度（DPG）

前面的 Policy Gradient、PPO、SAC 多数使用随机策略：

$$
\pi_\theta(a \mid s)
$$

连续控制任务中，也常使用确定性策略：

$$
a = \mu_\theta(s)
$$

#### 14.3.1 确定性策略 vs 随机性策略

| 对比项 | 随机策略 | 确定性策略 |
|---|---|---|
| 表达形式 | $\pi_\theta(a \mid s)$ | $a = \mu_\theta(s)$ |
| 输出 | 动作分布或动作概率 | 一个确定动作 |
| 探索方式 | 从分布中采样 | 通常额外加噪声 |
| 适用场景 | 离散动作、需要随机性的策略 | 连续控制、动作维度较高 |
| 代表算法 | REINFORCE、A2C、PPO、SAC | DPG、DDPG、TD3 |

随机策略会回答：

```text
在状态 s 下，每个动作的概率是多少？
```

确定性策略会回答：

```text
在状态 s 下，直接输出哪个连续动作？
```

例如机械臂控制中，动作可能是多个关节的连续力矩。直接输出一个动作向量通常比维护完整动作分布更自然。

#### 14.3.2 DPG、DDPG、TD3 算法

**DPG（Deterministic Policy Gradient）** 的策略是：

$$
a = \mu_\theta(s)
$$

它使用 Critic $Q_w(s,a)$ 来评价动作，Actor 的目标是让 Critic 给出的 Q 值更大：

$$
J(\theta)
=
\mathbb{E}_{s \sim \mathcal{D}}
\left[
Q_w(s, \mu_\theta(s))
\right]
$$

确定性策略梯度定理给出：

$$
\nabla_\theta J(\theta)
=
\mathbb{E}_{s \sim \mathcal{D}}
\left[
\nabla_a Q_w(s,a)
\vert_{a=\mu_\theta(s)}
\nabla_\theta \mu_\theta(s)
\right]
$$

直觉是：

```text
Critic 告诉 Actor：
    当前动作 a 往哪个方向改，Q 值会变大

Actor 根据这个方向：
    调整 μθ(s)，让输出动作更容易获得高 Q
```

**DDPG（Deep Deterministic Policy Gradient）** 是 DPG 的深度学习版本。

它结合了：

- 确定性 Actor：$\mu_\theta(s)$
- Q Critic：$Q_w(s,a)$
- Replay Buffer
- Target Network
- 探索噪声

Critic 的 TD target 是：

$$
y_t
=
r_t
+
\gamma
Q_{w^-}
\left(
s_{t+1},
\mu_{\theta^-}(s_{t+1})
\right)
$$

Critic loss：

$$
\mathcal{L}_{critic}
=
\left(
y_t
-
Q_w(s_t,a_t)
\right)^2
$$

Actor loss 通常写成最小化负 Q：

$$
\mathcal{L}_{actor}
=
-
\mathbb{E}
\left[
Q_w(s, \mu_\theta(s))
\right]
$$

DDPG 的训练流程：

```text
1. Actor 输出确定性动作 μθ(s)
2. 为了探索，给动作加噪声：a = μθ(s) + noise
3. 和环境交互，存入 Replay Buffer
4. 采样 batch，更新 Critic
5. 用 Critic 的动作梯度更新 Actor
6. 软更新 target networks
```

软更新是：

$$
\theta^-
\leftarrow
\tau \theta
+
(1-\tau)\theta^-
$$

其中 $\tau$ 通常很小，例如 0.005。

**TD3（Twin Delayed DDPG）** 是 DDPG 的稳定性改进版本。

它主要修正 DDPG 的 Q 值高估和训练不稳定问题，有三个关键改进：

**第一，双 Critic。**

TD3 同时训练两个 Q 网络：

$$
Q_{w_1}(s,a), \quad Q_{w_2}(s,a)
$$

target 使用较小的那个：

$$
y_t
=
r_t
+
\gamma
\min_{i=1,2}
Q_{w_i^-}
\left(
s_{t+1},
\tilde{a}_{t+1}
\right)
$$

这样可以缓解 Q 值高估。

**第二，目标策略平滑。**

计算 target action 时加入裁剪后的噪声：

$$
\tilde{a}_{t+1}
=
\mu_{\theta^-}(s_{t+1})
+
\operatorname{clip}(\epsilon, -c, c)
$$

这样可以避免 Critic 只在某些尖锐动作点上过拟合。

**第三，延迟策略更新。**

Critic 每步都更新，Actor 隔几步才更新一次：

```text
每次训练：
    更新 Critic

每隔 d 步：
    更新 Actor
    更新 Target Network
```

因为 Critic 是 Actor 的学习信号来源，先让 Critic 更稳定，再更新 Actor，通常训练更稳。

最短对比：

| 算法 | 核心 | 稳定性机制 |
|---|---|---|
| DPG | 确定性策略梯度 | 理论框架 |
| DDPG | DPG + 深度网络 + Replay Buffer + Target Network | 探索噪声、软更新 |
| TD3 | DDPG 改进版 | 双 Critic、目标策略平滑、延迟 Actor 更新 |

一句话理解：

```text
DPG/DDPG/TD3 是连续动作控制里的确定性策略路线；
Actor 直接输出动作，Critic 告诉 Actor 这个动作该往哪个方向改。
```


## 15. 多智能体强化学习（MARL）

前面大多数内容默认只有一个智能体：

```text
一个 Agent
-> 在一个 Environment 中行动
-> 根据奖励更新自己的策略
```

**多智能体强化学习（Multi-Agent Reinforcement Learning, MARL）** 研究的是多个智能体同时学习和决策的场景。

它的典型结构是：

```text
多个 Agent 同时观察环境
-> 每个 Agent 选择自己的动作
-> 环境根据联合动作发生变化
-> 每个 Agent 得到奖励
-> 各自或共同更新策略
```

### 15.1 MARL 为什么更难

MARL 不只是“把单智能体 RL 复制多份”。它会带来几个额外问题。

**第一，环境对每个智能体来说会变得非平稳。**

在单智能体 RL 中，环境转移规律通常被看成固定的。但在 MARL 中，其他智能体也在学习，它们的策略会变：

```text
我今天面对的“环境”
= 真实环境 + 其他智能体当前策略
```

当其他智能体策略变化时，我看到的数据分布也会变化。

**第二，奖励归因更难。**

如果多个智能体共同完成任务，团队拿到了高奖励，很难判断：

```text
到底是谁的动作贡献最大？
哪个智能体应该被更多鼓励？
哪个动作其实拖了后腿？
```

这就是多智能体里的 Credit Assignment（信用分配）问题。

**第三，联合动作空间会迅速变大。**

如果有 $N$ 个智能体，每个智能体有 $m$ 个动作，联合动作数量是：

$$
m^N
$$

智能体数量增加后，直接枚举联合动作会很快变得不可行。

### 15.2 MARL 的建模方式

MARL 常用 **随机博弈（Stochastic Game）** 或 **Markov Game** 建模，可以看成 MDP 的多智能体扩展。

一个简化形式可以写成：

$$
\langle N, S, A_1, \ldots, A_N, P, R_1, \ldots, R_N, \gamma \rangle
$$

其中：

- $N$：智能体数量
- $S$：环境状态空间
- $A_i$：第 $i$ 个智能体的动作空间
- $(a_1, \ldots, a_N)$：所有智能体动作组成的联合动作
- $P(s' \mid s, a_1, \ldots, a_N)$：联合动作导致的状态转移概率
- $R_i$：第 $i$ 个智能体的奖励函数
- $\gamma$：折扣因子

如果每个智能体不能看到完整状态，而只能看到局部观测，也可以写成：

```text
Agent i 只能看到 observation oi
而不是完整状态 s
```

这类问题常和部分可观测、通信、协作策略一起讨论。

### 15.3 常见 MARL 任务类型

多智能体任务可以按奖励关系分成几类。

| 类型 | 奖励关系 | 典型例子 |
|---|---|---|
| 完全协作 | 所有智能体共享团队奖励 | 多机器人协同搬运、团队游戏 |
| 完全竞争 | 一个智能体收益常对应另一个损失 | 双人零和游戏 |
| 混合合作竞争 | 既有合作也有竞争 | 交通系统、市场竞价、多人游戏 |

最容易入门的是完全协作任务，因为可以把团队目标写成一个共享奖励：

```text
R1 = R2 = ... = RN = R_team
```

但即使共享奖励，仍然需要解决信用分配和联合动作空间膨胀问题。

### 15.4 MARL 的训练架构：独立学习与 CTDE

一种最简单做法是 **Independent Learning（独立学习）**。

每个智能体把其他智能体都当成环境的一部分，各自训练自己的策略：

```text
Agent 1 学 π1
Agent 2 学 π2
Agent 3 学 π3
...
```

这种方法简单，但问题是其他智能体也在变，导致每个智能体看到的环境非平稳。

更常见的现代架构是 **CTDE（Centralized Training, Decentralized Execution）**：

```text
训练时：可以使用全局状态、其他智能体动作、团队信息
执行时：每个智能体只根据自己的局部观测独立行动
```

它的优势是：

- 训练时信息更充分，Critic 可以更准确评估联合行为
- 执行时不要求中心控制器，适合真实分布式系统
- 能兼顾训练稳定性和部署可行性

很多 MARL 算法都可以放进 CTDE 框架里理解。

### 15.5 典型 MARL 算法

**IQL（Independent Q-Learning）** 是最直接的多智能体 Q-Learning 版本。

每个智能体维护自己的 Q 函数：

```text
Qi(oi, ai)
```

其中 $o_i$ 是第 $i$ 个智能体的局部观测，$a_i$ 是它自己的动作。

IQL 简单、容易实现，但会把其他智能体的变化当成环境噪声，因此稳定性有限。

**VDN（Value Decomposition Networks）** 用于合作任务。

它把团队 Q 值分解成每个智能体局部 Q 值的和：

$$
Q_{tot} = \sum_i Q_i(o_i, a_i)
$$

这样训练时可以优化团队价值，执行时每个智能体仍然根据自己的 $Q_i$ 选择动作。

**QMIX** 也是合作 MARL 的经典方法。

它不要求团队 Q 值只是简单求和，而是用一个混合网络把各个智能体的 $Q_i$ 组合成 $Q_{tot}$，同时保持单调性约束：

```text
每个 Qi 变大时，Qtot 不会变小
```

这样可以保证训练时优化团队 Q 值，执行时仍然能让各智能体分散选择局部最优动作。

**MADDPG** 可以理解成 DDPG 的多智能体扩展。

它常使用 CTDE：

```text
Actor：每个智能体只看自己的观测，输出自己的动作
Critic：训练时看到全局状态和所有智能体动作
```

因此它适合连续动作空间下的合作或混合博弈任务。

**MAPPO** 是 PPO 在多智能体场景中的常见扩展。

它通常使用集中式 Critic 和分散式 Actor：

```text
多个 Actor：各智能体执行自己的策略
集中式 Critic：训练时评估全局联合状态
```

由于 PPO 本身比较稳定，MAPPO 在很多多智能体基准任务中是一个常用强基线。

可以先这样记：

```text
IQL：每个智能体各学各的 Q
VDN/QMIX：合作任务中分解团队价值
MADDPG：连续动作，多智能体 Actor-Critic
MAPPO：多智能体 PPO，常配合 CTDE
```

### 15.6 MARL 的典型训练流程与核心损失

MARL 的算法很多，但可以先抓住三类常见训练范式。

**第一类：独立学习 IQL。**

IQL 把每个智能体都当成一个普通 Q-Learning 智能体：

```text
for 每个智能体 i:
    根据局部观测 oi 选择动作 ai
环境接收联合动作 (a1, ..., aN)
返回下一观测、奖励、done
for 每个智能体 i:
    用自己的经验更新 Qi(oi, ai)
```

如果每个智能体使用自己的奖励 $r_i$，更新目标可以写成：

$$
y_i = r_i + \gamma \max_{a_i'} Q_i(o_i', a_i')
$$

$$
\mathcal{L}_i =
\left(
y_i - Q_i(o_i, a_i)
\right)^2
$$

如果是共享团队奖励，也可以把 $r_i$ 换成 $r_{team}$。

IQL 的优点是简单，缺点是没有显式处理其他智能体策略变化带来的非平稳性。

**第二类：价值分解 VDN / QMIX。**

在完全协作任务中，经常希望训练一个团队价值函数 $Q_{tot}$，但执行时每个智能体仍然分散行动。

VDN 的分解是：

$$
Q_{tot}(\mathbf{o}, \mathbf{a}) = \sum_i Q_i(o_i, a_i)
$$

其中：

- $\mathbf{o}$：所有智能体观测的组合
- $\mathbf{a}$：所有智能体动作的组合
- $Q_i$：第 $i$ 个智能体的局部动作价值

团队 TD target 可以写成：

$$
y = r_{team} + \gamma \max_{\mathbf{a}'} Q_{tot}^{target}(\mathbf{o}', \mathbf{a}')
$$

损失是：

$$
\mathcal{L} =
\left(
y - Q_{tot}(\mathbf{o}, \mathbf{a})
\right)^2
$$

QMIX 和 VDN 的不同点是：QMIX 用 mixing network 组合各个 $Q_i$，而不是简单相加：

$$
Q_{tot} = f_{mix}(Q_1, Q_2, \ldots, Q_N, s)
$$

并约束：

$$
\frac{\partial Q_{tot}}{\partial Q_i} \ge 0
$$

这个单调性约束保证：每个智能体局部选择更高 $Q_i$ 的动作时，不会让团队 $Q_{tot}$ 变差。

**第三类：集中式 Critic + 分散式 Actor。**

MADDPG、MAPPO 这类方法常采用 CTDE：

```text
训练时：
    Actor_i 根据局部观测 oi 输出动作 ai
    Centralized Critic 看到全局状态 s 和联合动作 (a1, ..., aN)
    Critic 给出更稳定的价值或优势估计

执行时：
    每个 Actor_i 只看自己的 oi
    独立输出 ai
```

可以把集中式 Critic 写成：

$$
Q_i(s, a_1, a_2, \ldots, a_N)
$$

它评估的是：在全局状态 $s$ 下，所有智能体采取联合动作时，对第 $i$ 个智能体有多好。

Actor 更新时，智能体 $i$ 只更新自己的策略参数：

$$
\nabla_{\theta_i} J_i
\approx
\mathbb{E}
\left[
\nabla_{\theta_i} \log \pi_{\theta_i}(a_i \mid o_i)
A_i(s, \mathbf{a})
\right]
$$

其中 $A_i(s, \mathbf{a})$ 可以由集中式 Critic 估计。

最短记忆：

```text
IQL：各学各的，简单但不稳
VDN/QMIX：合作任务中学团队 Q，再分解到个体
MADDPG/MAPPO：训练时集中评价，执行时分散行动
```

## 16. 模仿学习（IL）

强化学习通常依靠奖励信号和试错学习策略。但有些任务里，奖励很难设计，或者试错代价太高。

例如：

- 自动驾驶不能随意试错
- 机器人不能靠大量失败动作撞坏设备
- 对话系统很难给每一步动作设计精确奖励
- 人类专家已经有大量示范数据

这时可以考虑 **模仿学习（Imitation Learning, IL）**。

它的目标是：

> 不直接从奖励开始学，而是先从专家示范中学习“专家会怎么做”。

专家数据通常长这样：

```text
(s1, a1), (s2, a2), (s3, a3), ...
```

也就是在某个状态或观测下，专家采取了什么动作。

### 16.1 行为克隆（BC）

**行为克隆（Behavior Cloning, BC）** 是最直接的模仿学习方法。

它把模仿学习变成监督学习：

```text
输入：专家看到的状态 s
标签：专家采取的动作 a
训练目标：让模型在 s 下输出和专家一样的动作
```

如果动作是离散的，可以用分类损失：

$$
\mathcal{L}_{BC}(\theta)
= - \mathbb{E}_{(s,a) \sim D_E}
\left[
\log \pi_\theta(a \mid s)
\right]
$$

其中：

- $D_E$：专家示范数据集
- $\pi_\theta(a \mid s)$：当前策略在状态 $s$ 下选择专家动作 $a$ 的概率
- 损失越小，表示策略越像专家

BC 的优点是简单、高效、容易实现。

它的主要问题是 **分布偏移（Distribution Shift）**。

训练数据里都是专家走过的状态，但模型一旦犯小错，就可能进入专家数据中很少出现的状态：

```text
专家数据覆盖的是专家轨迹
模型执行时可能偏离专家轨迹
偏离后遇到陌生状态
模型更容易继续犯错
错误逐步累积
```

所以 BC 适合专家数据覆盖充分、动作容错率较高的任务；如果任务对连续决策误差很敏感，就需要更强的方法。

### 16.2 逆向强化学习（IRL）

**逆向强化学习（Inverse Reinforcement Learning, IRL）** 的思路不是直接模仿动作，而是反推专家背后的奖励函数。

普通强化学习是：

```text
给定奖励函数 R
-> 学习最优策略 π
```

IRL 则反过来：

```text
给定专家策略或专家轨迹
-> 推断什么奖励函数 R 能解释专家行为
-> 再用这个奖励函数训练策略
```

例如看到专家总是绕开障碍、选择平稳路径，IRL 希望学出类似这样的奖励：

```text
接近目标：正奖励
碰撞风险：负奖励
路径不平滑：负奖励
```

IRL 的价值在于：有些任务中，人类很难手写奖励函数，但可以提供示范。

它的难点是：能解释同一组专家轨迹的奖励函数可能不止一个。也就是说，IRL 通常存在不唯一性，需要额外假设或正则化。

### 16.3 生成对抗模仿学习（GAIL）

**GAIL（Generative Adversarial Imitation Learning）** 把模仿学习和 GAN 的思想结合起来。

它不显式恢复一个人工可解释的奖励函数，而是训练一个判别器区分：

```text
专家产生的状态-动作对
当前策略产生的状态-动作对
```

结构可以理解成：

```text
Policy πθ：生成行为轨迹
Discriminator D：判断这段行为像不像专家
```

训练目标是：

- 判别器更擅长区分专家行为和策略行为
- 策略尽量生成让判别器分不出来的行为

也就是：

```text
如果策略行为越来越像专家，
判别器就越来越难判断它是不是专家数据。
```

从强化学习角度看，判别器可以给策略提供一种学习信号：

```text
越像专家的状态-动作对，奖励越高
越不像专家的状态-动作对，奖励越低
```

GAIL 的优点是能学习到更接近专家 occupancy measure 的行为分布，而不是只做逐状态动作匹配。

它的代价是训练更复杂，通常需要交替优化策略和判别器。

### 16.4 IL、RL 和离线数据的关系

模仿学习和强化学习可以这样区分：

| 方法 | 主要信号 | 学什么 | 典型问题 |
|---|---|---|---|
| BC | 专家动作标签 | 直接模仿专家动作 | 分布偏移 |
| IRL | 专家轨迹 | 反推奖励函数 | 奖励不唯一、计算复杂 |
| GAIL | 专家轨迹 + 判别器 | 让策略行为分布像专家 | 训练复杂 |
| RL | 奖励函数 | 最大化长期回报 | 奖励设计和探索成本 |

很多实际系统会把它们组合起来：

```text
先用 BC 从专家数据 warm start
-> 再用 RL 或 Offline RL 继续优化
-> 必要时用人类反馈修正奖励或偏好
```

一句话理解：

```text
模仿学习解决的是：
当奖励难设计或试错成本高时，先从专家行为里学一个可用策略。
```

### 16.5 IL 的算法流程与更正式目标

模仿学习可以按“是否显式学习奖励”分成三条路线。

**行为克隆 BC：直接学专家动作。**

训练流程是：

```text
收集专家数据 D_E = {(s, a)}
-> 把状态 s 当输入，把专家动作 a 当标签
-> 用监督学习训练策略 πθ(a|s)
-> 部署策略，让它自己闭环行动
```

目标函数是最大化专家动作的似然，也就是最小化负对数似然：

$$
\mathcal{L}_{BC}(\theta)
=
- \frac{1}{|D_E|}
\sum_{(s,a) \in D_E}
\log \pi_\theta(a \mid s)
$$

如果动作是连续值，策略可以输出高斯分布参数：

```text
πθ(a|s) = Normal(μθ(s), σθ(s))
```

这时 BC 就是在最大化专家动作在该分布下的概率。

**DAgger：缓解行为克隆的分布偏移。**

BC 最大的问题是模型部署后会进入专家数据没覆盖的状态。DAgger（Dataset Aggregation）的做法是让当前策略也参与采样：

```text
1. 用当前策略 πθ 跑环境，收集它实际会遇到的状态
2. 请专家给这些状态标注正确动作
3. 把新标注并入训练集
4. 重新训练或继续训练 πθ
5. 重复上述过程
```

它的关键不是换了损失函数，而是让训练数据逐渐覆盖“模型自己会走到的状态”。

**IRL：先学奖励，再做 RL。**

IRL 的核心目标是找到一个奖励函数 $R_\phi(s,a)$，让专家策略在这个奖励下显得合理。

最大熵 IRL 常用的直觉是：

```text
专家轨迹获得高奖励
非专家轨迹获得较低奖励
同时保留轨迹分布的不确定性
```

可以写成一种简化目标：

$$
\max_\phi
\mathbb{E}_{\tau \sim D_E}
\left[
\sum_t R_\phi(s_t, a_t)
\right]
-
\log Z_\phi
$$

其中 $Z_\phi$ 是归一化项，用来考虑所有可能轨迹的奖励总量。

学到 $R_\phi$ 后，再用普通 RL 训练策略：

```text
专家轨迹 -> 学奖励 Rφ
Rφ -> 作为环境奖励
RL -> 学策略 πθ
```

**GAIL：用判别器提供模仿奖励。**

GAIL 的目标可以写成：

$$
\min_\pi \max_D
\mathbb{E}_{(s,a) \sim D_E}
[\log D(s,a)]
+
\mathbb{E}_{(s,a) \sim \pi}
[\log(1 - D(s,a))]
-
\lambda H(\pi)
$$

其中：

- $D(s,a)$：判别器认为状态-动作对来自专家的概率
- $\pi$：当前策略
- $H(\pi)$：策略熵，用来鼓励策略不要过早变得单一
- $\lambda$：熵正则权重

训练流程是：

```text
1. 用当前策略 π 采样轨迹
2. 用专家轨迹和策略轨迹训练判别器 D
3. 把 D 的输出转成奖励信号
4. 用 RL 更新策略 π，让它更像专家
5. 重复 1-4
```

GAIL 和 BC 的关键差异是：

```text
BC：逐状态模仿专家动作
GAIL：让整个状态-动作分布像专家
```

## 17. Offline RL 与离线策略评估（OPE）

前面的强化学习算法大多默认智能体可以持续和环境交互：

```text
当前策略产生动作
-> 环境返回奖励和下一状态
-> 策略根据新数据继续更新
```

但很多真实业务不能这样做。推荐、广告、自动驾驶、医疗、客服策略、金融风控等场景里，随意在线试错的成本很高，甚至不被允许。

这时常见的数据形式是历史日志：

```text
D = {(s, a, r, s', done)}
```

这些数据由过去某个策略采集，称为 **行为策略（behavior policy）**。Offline RL 的目标是：不再和真实环境交互，只用固定数据集 $D$ 学出一个更好的策略。

### 17.1 Online RL、Off-Policy RL 与 Offline RL 的区别

这三个概念容易混淆。

| 概念 | 数据来源 | 训练时能否继续采样 | 核心问题 |
|---|---|---:|---|
| Online RL | 当前策略或探索策略和环境实时交互 | 能 | 如何高效探索并提升回报 |
| Off-Policy RL | 数据可以来自不同于目标策略的行为策略 | 通常能继续采样 | 如何利用旧策略数据学习目标策略 |
| Offline RL | 固定历史数据集 | 不能 | 如何避免学到数据外的危险动作 |

Off-policy 只是在说：

```text
行为策略 != 目标策略
```

Offline RL 额外强调：

```text
训练过程中不能再向环境要新数据
```

所以 Offline RL 比普通 off-policy 更严格。Q-Learning、DQN 也可以用旧数据更新，但如果训练中还能继续探索环境，它们仍然不等于 Offline RL。

最短理解：

```text
Off-policy：数据可以不是当前策略采的
Offline RL：只有一份固定历史数据，不能再试错补数据
```

### 17.2 Offline RL 为什么更难：分布偏移与外推误差

Offline RL 最大的问题是 **分布偏移（distribution shift）**。

历史数据只覆盖了一部分状态和动作：

```text
日志里经常出现的动作：模型有足够样本学习
日志里很少出现的动作：模型只能猜
日志里完全没出现的动作：模型没有可靠依据
```

如果算法仍然像 Q-Learning 一样做最大化：

$$
\max_a Q(s', a)
$$

它可能会选中某个数据里很少出现、但被 Q 网络错误高估的动作。

这种问题叫 **外推误差（extrapolation error）**：

```text
模型在数据分布外做预测
-> Q 值可能虚高
-> 策略选择这些虚高动作
-> 但离线数据无法纠正错误
-> 策略越学越偏
```

Online RL 中，如果模型选错了动作，还能从环境拿到真实反馈并修正；Offline RL 中没有这个机会。

因此 Offline RL 的核心不是“如何更大胆探索”，而是：

```text
在历史数据支持的范围内改进策略
避免对数据外动作过度乐观
```

### 17.3 历史日志、行为策略与数据覆盖度

Offline RL 的效果高度依赖数据质量。

一个历史数据集通常隐含三个问题：

**第一，行为策略是什么。**

日志数据可能来自：

- 人类专家
- 旧版推荐系统
- 规则策略
- 随机探索策略
- 多个历史策略混合

行为策略越保守，数据覆盖越窄；行为策略越多样，数据覆盖越广，但数据质量可能更不稳定。

**第二，动作覆盖是否足够。**

如果某个状态下只见过动作 A，从没见过动作 B，那么模型很难可靠判断 B 是否更好。

可以这样理解：

```text
数据覆盖足够：可以做一定策略改进
数据覆盖很窄：更接近模仿学习，只能保守复现已有行为
```

**第三，奖励是否可靠。**

历史日志中的 reward 可能来自点击、成交、停留时长、人工评分或规则结果。

这些 reward 常有偏差：

- 点击不一定代表长期满意
- 短期转化不一定代表长期价值
- 人工评分可能不一致
- 日志只记录已展示动作的反馈，没展示的动作没有反事实结果

所以 Offline RL 不是只把日志丢进算法，还要先判断数据是否支持策略改进。

### 17.4 Offline RL 与模仿学习的关系

模仿学习和 Offline RL 都使用已有数据，但目标不同。

| 方法 | 数据 | 目标 | 是否显式优化奖励 |
|---|---|---|---:|
| Behavior Cloning | $(s, a)$ 专家示范 | 模仿数据里的动作 | 否 |
| Offline RL | $(s, a, r, s')$ 历史轨迹 | 在数据支持范围内提高回报 | 是 |
| Online RL | 实时交互样本 | 通过探索持续改进策略 | 是 |

BC 的目标是：

```text
数据里怎么做，我就怎么做
```

Offline RL 的目标是：

```text
在历史数据支持的动作范围内，找出长期回报更高的策略
```

如果历史数据主要来自高质量专家，BC 往往是很强的基线。

如果历史数据中有不同质量的动作，并且有可靠 reward，Offline RL 才有机会超过 BC。

实际工程里常见组合是：

```text
先用 BC 学一个稳定初始策略
-> 再用 Offline RL 做保守策略改进
-> 离线评估通过后，小流量在线验证
```

### 17.5 离线策略评估（OPE）：上线前如何评估新策略

**离线策略评估（Off-Policy Evaluation, OPE）** 要解决的问题是：

> 只有旧策略采集的日志，怎么估计新策略上线后会拿到多少回报？

这在推荐、广告、搜索排序中尤其重要。不能每个新策略都直接全量上线试错。

OPE 的困难在于反事实缺失：

```text
日志记录了旧策略实际选择的动作及结果
但没有记录“如果当时选另一个动作会怎样”
```

常见 OPE 方法包括：

**第一，重要性采样（IPS）。**

如果知道旧策略选择动作的概率 $\pi_b(a|s)$，可以用新旧策略概率比修正样本权重：

$$
\rho_t =
\frac{
\pi_e(a_t \mid s_t)
}{
\pi_b(a_t \mid s_t)
}
$$

其中：

- $\pi_b$：行为策略，采集日志的旧策略
- $\pi_e$：评估策略，准备上线的新策略

直觉是：

```text
新策略更可能选择日志中的这个动作 -> 样本权重大
新策略不太可能选择这个动作 -> 样本权重小
```

IPS 的问题是方差可能很大，尤其当 $\pi_b(a|s)$ 很小时，权重会爆炸。

**第二，加权重要性采样（WIS）。**

WIS 会对权重做归一化，降低方差：

$$
\hat{V}_{WIS}
=
\frac{
\sum_i \rho_i R_i
}{
\sum_i \rho_i
}
$$

它通常比 IPS 稳定，但可能引入一定偏差。

**第三，Doubly Robust（DR）。**

DR 同时使用：

```text
一个回报模型 / Q 模型
+ 重要性采样修正
```

它的思想是：如果回报模型还可以，就用模型估计；如果日志动作和新策略重合，也利用真实日志做校正。

OPE 的工程结论是：

```text
OPE 不能完全替代线上实验
但可以过滤明显危险或无效的策略
```

### 17.6 Offline RL 代表算法：BCQ、CQL、IQL

Offline RL 算法很多，但大多数都在解决同一个问题：

```text
不要让策略选择数据集里缺乏支持的动作
```

**BCQ（Batch-Constrained Q-learning）** 的思路是限制候选动作来自数据分布附近。

它会学习一个生成模型，生成“像历史数据中出现过”的动作，再在这些候选动作里选 Q 值高的动作：

```text
状态 s
-> 生成若干接近数据分布的动作
-> 用 Q 网络打分
-> 选择其中 Q 值最高的动作
```

BCQ 的核心是：

```text
只在数据支持的动作附近做改进
```

**CQL（Conservative Q-Learning）** 的思路是让 Q 函数保守。

它会压低数据外动作的 Q 值，避免策略被虚高 Q 值吸引：

```text
数据中的动作：允许 Q 值较高
数据外的动作：主动降低 Q 值
```

所以 CQL 可以理解成：

```text
宁可低估，也不要高估没见过的动作
```

**IQL（Implicit Q-Learning）** 的思路是不显式查询数据外动作的最大 Q。

它通过 value expectile regression 和 advantage-weighted behavior cloning，在不直接做 $\max_a Q(s,a)$ 的情况下学习策略。

直觉是：

```text
从数据里找出相对更好的动作
提高这些动作的概率
避免对未见动作做激进最大化
```

三者可以这样对比：

| 算法 | 核心约束 | 直觉 |
|---|---|---|
| BCQ | 限制动作接近数据分布 | 不要选日志外动作 |
| CQL | 保守压低数据外 Q 值 | 不要相信虚高 Q |
| IQL | 避免显式最大化数据外动作 | 只强化数据中相对好的动作 |

### 17.7 Offline RL 的典型应用与落地流程

Offline RL 适合以下场景：

| 场景 | 为什么适合 Offline RL |
|---|---|
| 推荐系统 | 有大量历史曝光、点击、转化日志，直接大规模试错风险高 |
| 广告出价 | 历史竞价和转化数据丰富，但错误策略会直接损失预算 |
| 自动驾驶 | 真实道路试错危险，通常依赖历史驾驶数据和仿真 |
| 客服策略 | 有历史对话和满意度数据，但不能随意用用户试错 |
| 医疗决策 | 历史病例数据存在，在线探索通常不符合伦理 |
| 工业控制 | 设备运行日志丰富，错误策略可能造成安全事故 |

一个保守的落地流程可以是：

```text
1. 收集并清洗历史日志
2. 分析行为策略和数据覆盖度
3. 训练 BC 作为基线策略
4. 训练 Offline RL 策略做保守改进
5. 用 OPE 和离线指标筛掉高风险策略
6. 在仿真或小流量环境验证
7. 逐步上线，并持续监控真实指标
```

最短总结：

```text
Offline RL 不是“没有环境也能随便学”；
它是在历史数据支持范围内，尽量安全地做策略改进。
OPE 则是上线前估计新策略风险和收益的工具。
```

## 18. 强化学习高级拓展

前面的章节主要覆盖了 Model-Free RL 的基础路线：

```text
Value-Based：Q-Learning / DQN
Policy-Based：Policy Gradient / REINFORCE
Actor-Critic：Actor + Critic
```

这一节补充三个常见高级方向：Model-Based RL、分层强化学习和分布价值强化学习。

### 18.1 基于环境模型的方法（Model-Based RL）

Model-Free 方法不显式学习环境转移，只直接学习价值或策略。

Model-Based RL 则尝试学习或使用环境模型：

```text
模型：给定当前状态 s 和动作 a
预测：下一状态 s' 和奖励 r
```

也就是学习：

$$
\hat{P}(s' \mid s, a), \quad \hat{R}(s, a)
$$

有了模型后，智能体可以在模型里做规划：

```text
真实环境采样少量数据
-> 学习环境模型
-> 在模型中模拟未来
-> 用模拟结果改进策略
```

典型思路包括：

- **Dyna**：真实经验更新价值函数，同时用学到的模型生成模拟经验继续更新
- **MCTS**：从当前状态向未来展开搜索树，用模拟结果评估动作
- **World Models**：用神经网络学习环境的压缩动态表示，再在模型空间中训练策略
- **MuZero**：不直接预测真实环境细节，而是学习对规划有用的隐状态、奖励和价值

Model-Based RL 的优点是样本效率高，因为模型可以反复模拟。

它的主要风险是模型误差：

```text
模型预测有偏差
-> 策略在错误模型里优化
-> 多步模拟时误差累积
-> 真实环境表现变差
```

一句话理解：

```text
Model-Based RL = 先学一个“环境近似器”，再利用它做规划或生成训练数据。
```

#### 18.1.1 Model-Based RL 的基本训练闭环

Model-Based RL 通常有两个学习对象：

```text
环境模型 Mφ：预测下一状态和奖励
策略或价值函数：利用模型做规划或学习
```

环境模型可以写成：

$$
\hat{s}_{t+1}, \hat{r}_{t+1}
=
M_\phi(s_t, a_t)
$$

如果模型直接预测下一状态和奖励，可以用监督学习训练：

$$
\mathcal{L}_{model}(\phi)
=
\left\|
\hat{s}_{t+1} - s_{t+1}
\right\|^2
+
\left(
\hat{r}_{t+1} - r_{t+1}
\right)^2
$$

基本流程是：

```text
1. 用当前策略和真实环境交互，收集真实数据
2. 用真实数据训练环境模型 Mφ
3. 在模型 Mφ 中 rollout，生成模拟轨迹
4. 用真实轨迹 + 模拟轨迹更新策略或价值函数
5. 回到真实环境继续采样，修正模型误差
```

Dyna 类方法可以压缩成：

```text
真实经验：用于直接更新 Q 或 V
模型经验：从学到的模型中模拟出来，也用于更新 Q 或 V
```

如果用 Q-Learning 更新，真实经验和模拟经验都可以套同一个 TD 目标：

$$
Q(s,a)
\leftarrow
Q(s,a)
+
\alpha
\left[
r + \gamma \max_{a'} Q(s',a') - Q(s,a)
\right]
$$

区别只是 $(s,a,r,s')$ 来自真实环境还是来自模型。

### 18.2 分层强化学习（HRL）

**分层强化学习（Hierarchical Reinforcement Learning, HRL）** 试图把复杂任务拆成不同时间尺度的决策。

普通 RL 每一步都直接选择底层动作：

```text
每一步选择：向左、向右、加速、减速、抓取...
```

HRL 会引入更高层的子目标或技能：

```text
高层策略：决定当前子目标
低层策略：执行具体动作完成子目标
```

例如机器人任务可以拆成：

```text
高层：走到桌子旁 -> 抓起杯子 -> 移动到水槽
低层：每个阶段控制关节和步态
```

常见概念包括：

- **Option**：一个可持续多步的技能或子策略
- **Manager-Worker**：Manager 选择子目标，Worker 执行底层动作
- **Temporal Abstraction**：一个高层动作对应多个底层时间步

HRL 的优势是：

- 降低长序列任务的探索难度
- 复用已经学会的技能
- 让策略结构更接近人类分层规划

它的难点是：

- 子目标怎么定义
- 技能什么时候开始和终止
- 高层奖励与低层奖励如何设计

一句话理解：

```text
HRL = 不直接学每一步怎么动，而是先学“做什么子任务”，再学“如何完成子任务”。
```

#### 18.2.1 Option 框架：把技能当成高层动作

HRL 里最经典的形式之一是 **Option**。

一个 option 可以写成三元组：

$$
o = \langle I_o, \pi_o, \beta_o \rangle
$$

其中：

- $I_o$：这个 option 可以在哪些状态启动
- $\pi_o(a \mid s)$：option 内部的低层策略
- $\beta_o(s)$：到达状态 $s$ 时，option 终止的概率

普通 MDP 每一步都选择原子动作：

```text
s_t -> 选择底层动作 a_t -> s_{t+1}
```

Option 框架里，高层先选择一个技能：

```text
s_t -> 高层选择 option o
     -> option 内部策略 πo 连续执行多步动作
     -> option 终止后回到高层重新选择
```

如果某个 option 执行了 $k$ 步，高层看到的回报可以写成：

$$
G_t^{option}
=
R_{t+1}
+ \gamma R_{t+2}
+ \cdots
+ \gamma^{k-1}R_{t+k}
+ \gamma^k V(S_{t+k})
$$

这和 n-step TD 很像，只是中间这 $k$ 步不是任意采样，而是由同一个 option 内部策略控制。

一句话理解：

```text
Option = 可持续多步的高层动作；
高层负责选技能，低层负责把技能执行完。
```

### 18.3 分布价值强化学习（Distributional RL）

普通价值函数学习的是期望回报：

$$
Q(s, a) = \mathbb{E}[G_t \mid S_t=s, A_t=a]
$$

但从同一个状态-动作对出发，未来回报可能有多种结果。

例如两个动作的期望回报都等于 5：

```text
动作 A：稳定得到 5
动作 B：一半概率得到 0，一半概率得到 10
```

普通 Q 值会认为它们一样，因为期望都是 5。但它们的风险结构完全不同。

**分布价值强化学习（Distributional RL）** 不只学习期望值，而是学习回报分布：

$$
Z(s, a) \approx \text{Return 的概率分布}
$$

然后期望 Q 值只是这个分布的平均值：

$$
Q(s, a) = \mathbb{E}[Z(s, a)]
$$

典型算法包括：

- **C51**：把回报分布表示成固定数量的离散支撑点
- **QR-DQN**：用分位数回归表示回报分布
- **IQN**：用隐式分位数网络更灵活地表示分布

Distributional RL 的价值在于：

- 保留回报不确定性信息
- 对奖励分布复杂的任务更有表达能力
- 常能提升 DQN 类算法的训练表现

一句话理解：

```text
普通 Q 学“平均能拿多少分”；
Distributional RL 学“可能拿到哪些分，各自概率多大”。
```

#### 18.3.1 分布式贝尔曼方程

普通贝尔曼方程更新的是期望值：

$$
Q(s,a)
\leftarrow
\mathbb{E}
\left[
R_{t+1}
+
\gamma \max_{a'} Q(S_{t+1},a')
\right]
$$

Distributional RL 更新的是随机变量本身。

把回报随机变量写成 $Z(s,a)$，则分布式贝尔曼最优形式可以理解为：

$$
Z(s,a)
\overset{D}{=}
R_{t+1}
+
\gamma Z(S_{t+1}, a^*)
$$

其中：

$$
a^* = \arg\max_{a'} \mathbb{E}[Z(S_{t+1}, a')]
$$

$\overset{D}{=}$ 表示两边在分布意义上相等，而不只是期望值相等。

C51 的做法是把可能的回报范围切成固定支撑点：

```text
z1, z2, ..., zN
```

网络输出每个支撑点的概率：

```text
Z(s,a) -> [p1, p2, ..., pN]
```

QR-DQN 则不固定概率点，而是学习不同分位数位置的回报值：

```text
低分位：偏悲观结果
中位数：典型结果
高分位：偏乐观结果
```

这让智能体不只知道“平均值”，还知道回报分布的大致形状。

### 18.4 三类高级方向的最短对比

| 方向 | 解决的问题 | 核心做法 |
|---|---|---|
| Model-Based RL | 真实交互样本贵 | 学环境模型，用模型规划或模拟 |
| HRL | 长时序任务难探索 | 把任务拆成高层子目标和低层动作 |
| Distributional RL | 只看期望会丢失风险信息 | 学回报分布而不是单个期望值 |

这三类方法不是互斥的。实际研究和工程中，经常会把它们与 DQN、Actor-Critic、PPO 等基础框架结合。

## 19. 奖励设计、安全约束与 Reward Hacking

强化学习里，算法只负责优化目标；真正决定智能体行为边界的，往往是奖励函数和约束条件。

很多 RL 项目失败，不是因为 PPO、DQN 或 SAC 不够强，而是因为：

```text
奖励定义错了
约束没有写进训练目标
评估指标和真实目标不一致
智能体学会钻奖励函数空子
```

所以在工程里，建模顺序通常不是“先选算法”，而是先问：

```text
什么行为应该被鼓励？
什么行为必须被禁止？
短期奖励和长期目标是否一致？
有没有安全底线不能被 reward trade-off 掉？
```

### 19.1 奖励设计：稀疏奖励、密集奖励与奖励塑形

奖励函数把任务目标变成可优化信号。

最简单的奖励是 **稀疏奖励（sparse reward）**：

```text
任务成功：+1
任务失败：0 或 -1
中间过程：没有奖励
```

稀疏奖励的优点是目标清晰，不容易引入过多人工偏好；缺点是学习很慢，尤其当成功很少发生时，智能体很难知道哪些中间动作是有用的。

另一类是 **密集奖励（dense reward）**：

```text
离目标更近：+0.1
保持稳定：+0.05
碰撞：-1
能耗过高：-0.1
完成任务：+1
```

密集奖励能提供更频繁的学习信号，但也更容易写错。智能体可能优化中间指标，而不是最终目标。

例如机器人任务中，如果奖励写成：

```text
离目标越近 reward 越高
```

智能体可能学会靠近目标但不完成抓取，因为“停在目标附近”已经能持续拿到不错的奖励。

**奖励塑形（reward shaping）** 是在原始任务奖励之外加入辅助奖励，帮助学习更快收敛。

一个常见原则是：辅助奖励应该引导探索，但不能改变最优策略本身。

可以这样区分：

| 奖励类型 | 作用 | 风险 |
|---|---|---|
| 终局奖励 | 定义最终目标 | 信号稀疏 |
| 过程奖励 | 提供中间反馈 | 可能诱导错误捷径 |
| 惩罚项 | 避免不良行为 | 过强会让策略保守 |
| 约束项 | 表达不能违反的边界 | 需要和 reward 区分清楚 |

最短判断：

```text
奖励告诉智能体“什么更好”；
约束告诉智能体“什么不能做”。
```

### 19.2 Reward Hacking：智能体钻奖励函数空子

**Reward Hacking** 指智能体找到了提高奖励的方法，但这种方法并不符合真实意图。

它不是训练失败，而是训练“太成功”：智能体真的在最大化你写下来的 reward，只是这个 reward 没有准确表达你想要的目标。

典型例子：

| 场景 | 设计的奖励 | 可能的 Reward Hacking |
|---|---|---|
| 游戏 | 分数越高越好 | 反复刷小怪，不推进任务 |
| 机器人 | 离目标越近奖励越高 | 停在目标附近，不完成操作 |
| 推荐 | 点击率越高越好 | 推荐标题党内容，损害长期满意度 |
| 客服 | 平均处理时长越短越好 | 快速结束对话，但问题没解决 |
| 内容推荐 | 互动率越高越好 | 推送刺激性内容，损害长期信任 |

Reward Hacking 常见原因包括：

- 奖励只覆盖了容易量化的指标
- 缺少对副作用的惩罚
- 短期指标替代了长期目标
- 训练环境和真实环境有差异
- 奖励模型或评估器本身有漏洞

缓解方式包括：

- 使用多指标评估，而不是只看单个 reward
- 加入人工抽检或规则检查
- 把长期指标纳入奖励或评估
- 对异常高 reward 的样本做案例分析
- 使用安全约束过滤明显不可接受行为

一句话：

```text
Reward Hacking 的本质是：智能体优化了指标，但没有完成真实目标。
```

### 19.3 Constrained RL 与 Safe RL：不只最大化奖励

很多任务不能只写成：

$$
\max_\pi \mathbb{E}[G]
$$

因为现实中还有安全、成本、合规、资源等硬约束。

例如：

```text
机器人：不能碰撞人或设备
自动驾驶：不能违反交通规则
推荐系统：不能推送违规内容
工业控制：不能超过温度或压力阈值
决策系统：不能泄露隐私或违反合规要求
```

这类问题可以用 **约束马尔可夫决策过程（Constrained MDP, CMDP）** 表示。

普通 MDP 优化奖励：

$$
\max_\pi J_R(\pi)
$$

CMDP 会额外加入成本约束：

$$
\max_\pi J_R(\pi)
$$

同时满足：

$$
J_C(\pi) \le d
$$

其中：

- $J_R(\pi)$：策略的期望回报
- $J_C(\pi)$：策略的期望成本，例如碰撞率、违规率、能耗
- $d$：允许的最大成本阈值

这和简单地把成本写进 reward 不完全一样。

如果写成：

```text
reward = task_reward - λ * safety_cost
```

智能体可能在高任务奖励和高安全风险之间做 trade-off。但某些约束不应该被 trade-off 掉，例如“不能撞人”“不能泄露隐私”。

所以工程上常把目标分成两类：

| 类型 | 含义 | 例子 |
|---|---|---|
| 优化目标 | 越高越好，可以权衡 | 得分、收益、效率、满意度 |
| 安全约束 | 不能超过边界 | 碰撞、违规、隐私泄露、危险动作 |

### 19.4 常见安全约束方法：Lagrangian、Shielding 与人类接管

**Lagrangian 方法** 会把约束转成带乘子的优化目标：

$$
\mathcal{L}(\pi, \lambda)
=
J_R(\pi)
-
\lambda (J_C(\pi) - d)
$$

其中 $\lambda$ 会根据约束违反情况动态调整：

```text
如果成本超过阈值 -> 增大 λ，让策略更重视安全
如果成本低于阈值 -> 减小 λ，让策略更重视任务回报
```

这种方法适合“成本可以量化，并且允许一定阈值”的任务。

**Shielding（安全屏蔽）** 是在策略动作真正执行前加一层安全过滤器。

流程是：

```text
策略输出动作 a
-> 安全模块检查动作是否会违反约束
-> 如果安全，执行 a
-> 如果不安全，替换为安全动作或触发停止
```

Shield 可以来自：

- 规则系统
- 控制理论约束
- 仿真预测
- 安全分类器
- 人工定义的动作白名单 / 黑名单

它的优点是部署时更稳，缺点是如果 shield 太强，策略可能学不到真正的安全行为，只是依赖外部拦截。

**人类接管（human intervention）** 常用于高风险场景。

例如自动驾驶、机器人、医疗辅助决策中，当系统置信度低或接近危险状态时，可以触发：

```text
暂停执行
请求人类确认
切换到保守策略
记录样本用于后续训练
```

人类接管不只是安全机制，也是一种数据收集方式：系统失败或接近失败的状态，往往正是最有价值的训练样本。

### 19.5 工程落地中的奖励与约束检查表

做 RL 建模时，可以用下面的检查表避免常见问题。

| 问题 | 要检查什么 |
|---|---|
| 目标是否明确 | reward 是否真的对应业务目标 |
| 是否只优化短期指标 | 点击、时长、得分是否会损害长期价值 |
| 是否存在安全底线 | 哪些行为不能通过高 reward 抵消 |
| 是否有副作用 | 策略是否会消耗资源、制造风险或影响其他用户 |
| 奖励是否可被刷 | 智能体是否能用捷径拿高分 |
| 约束是否可观测 | 系统能否检测碰撞、违规、隐私泄露等事件 |
| 评估是否覆盖极端情况 | 是否测试了边界状态、异常输入、长尾场景 |

一个实用建模顺序是：

```text
1. 写清楚最终业务目标
2. 区分优化目标和硬约束
3. 设计终局奖励和必要的过程奖励
4. 为关键风险设计 cost / constraint
5. 检查 reward hacking 的可能路径
6. 用离线评估、仿真、小流量上线逐步验证
7. 持续监控 reward、真实指标和安全指标是否背离
```

最短总结：

```text
Reward Design 解决“智能体追求什么”；
Safe RL 解决“智能体不能做什么”；
Reward Hacking 提醒我们：指标不是目标本身。
```

## 20. 强化学习的典型应用

学完前面的算法后，再看应用时不要只记“RL 可以用于哪些行业”，而要看一个任务能不能被写成：

```text
状态 / 观测是什么
动作是什么
奖励如何定义
是否能安全试错
是否需要长期优化
```

如果一个问题只有静态输入输出标签，通常先考虑监督学习；如果动作会影响后续状态，并且目标是长期累计收益，才更适合用强化学习。

典型应用可以按下面方式理解：

| 场景 | 状态 / 观测 | 动作 | 奖励信号 | 常见方法 |
|---|---|---|---|---|
| 游戏 AI | 棋盘、画面、单位状态 | 落子、移动、攻击 | 胜负、得分、阶段奖励 | DQN、PPO、MCTS、MARL |
| 机器人控制 | 传感器、关节角、视觉 | 力矩、速度、轨迹点 | 到达目标、稳定性、能耗、碰撞惩罚 | SAC、PPO、DDPG、TD3、Model-Based RL |
| 推荐与广告 | 用户画像、上下文、历史行为 | 推荐物品、排序、出价 | 点击、转化、长期留存、收益 | Bandit、Off-Policy Evaluation、Offline RL |
| 资源调度 | 队列、负载、机器状态 | 分配资源、调度任务、路由 | 吞吐量、延迟、成本、失败率 | Q-Learning、Actor-Critic、Model-Based RL |
| 自动驾驶 | 车辆状态、道路、障碍物 | 转向、加减速、轨迹规划 | 安全、舒适、效率、规则遵守 | IL、Offline RL、Model-Based RL、HRL |
| 多智能体系统 | 多个个体的局部观测和全局状态 | 每个智能体的局部动作 | 团队奖励或个体奖励 | IQL、VDN、QMIX、MADDPG、MAPPO |

几个实用判断：

- **能安全在线试错**：可以考虑 Online RL，例如游戏仿真、模拟器、部分机器人仿真。
- **真实试错代价高**：优先考虑模仿学习、Offline RL、仿真环境或 Model-Based RL。
- **奖励很难写清楚，但能比较好坏**：可以考虑偏好数据、奖励模型或人工反馈机制。
- **有不可违反的安全底线**：不要只写 reward 惩罚，应考虑 CMDP、shielding、规则拦截或人类接管。
- **结果可以自动判对错**：可以考虑规则奖励、验证器或测试驱动的训练信号。
- **多个决策者互相影响**：考虑 MARL，而不是简单把单智能体算法复制多份。

所以，强化学习落地的关键不只是选算法，而是先判断问题结构：

```text
有没有序列决策？
奖励能不能定义或学习？
数据来自在线交互还是历史日志？
探索失败的成本是否可接受？
是否需要多个智能体协同？
```

## 21. 强化学习与大模型训练

在大模型领域，强化学习最常被提到的是 **RLHF（Reinforcement Learning from Human Feedback）**。

如果说第 14 章回答的是“策略到底怎么更新”，那么这一章回答的是“这些策略优化方法为什么会出现在大模型训练里，以及它们各自扮演什么角色”。

它不是用来教模型“下一个 token 是什么”，而是用来让模型的输出更符合人类偏好，例如：

- 更有帮助
- 更安全
- 更符合指令
- 更少胡编乱造
- 更符合特定风格或价值偏好

可以先用一句话理解：

```text
预训练：让模型学会语言和知识
监督微调 SFT：让模型学会模仿高质量答案
强化学习 / 偏好优化：让模型朝更符合偏好的方向继续优化
```

### 21.1 大模型训练中的强化学习元素

如果把大模型对齐过程类比成强化学习问题，可以这样对应：

| 强化学习概念 | 大模型训练中的对应物 |
|---|---|
| Agent | 语言模型 |
| State / Observation | 用户 prompt、对话历史、上下文 |
| Action | 模型生成的 token，或者一整段回答 |
| Policy $\pi_\theta$ | 当前语言模型，给出下一个 token 或整段回答的概率 |
| Reward | 人类偏好、奖励模型分数、规则奖励、任务得分 |
| Trajectory | 一次完整生成过程，例如 prompt -> answer |

和游戏或机器人不同，大模型里的“动作”通常不是“向左、向右”这种离散小动作，而是生成 token 或整段文本。

因此可以这样理解：

```text
经典 RL：在环境中选动作，拿奖励
大模型 RL：在上下文中生成回答，根据偏好或奖励信号优化模型
```

### 21.2 大模型后训练总览：SFT、Reward Model、RLHF、DPO、GRPO

大模型后训练不是只有一种路线。可以先把它看成从“模仿高质量答案”走向“按偏好或奖励继续优化”的过程：

```text
预训练模型
  |
  v
SFT：用高质量指令-回答数据做监督微调
  |
  v
偏好 / 奖励信号
  |
  +--> RLHF + PPO：训练 Reward Model，再用 PPO 优化策略
  |
  +--> DPO：直接使用 chosen / rejected 偏好对优化策略
  |
  +--> GRPO / RLVR：用规则、测试或标准答案构造可验证奖励
  |
  v
对齐后的模型
```

这一章只建立总览：这些方法为什么和强化学习有关、各自扮演什么角色。具体的 Reward Model、PPO-RLHF、RLAIF、GRPO/RLVR 和 DPO 训练细节，放到第 22 章展开。

### 21.3 PPO、GRPO、DPO 分别在做什么

大模型训练里经常会看到 PPO、GRPO、DPO 等名词。它们都和“偏好优化”有关，但含义不同。

**PPO（Proximal Policy Optimization）** 是一种经典强化学习算法。

在 RLHF 中，PPO 通常用来更新策略模型 $\pi_\theta$，让模型生成更高奖励的回答，同时通过 KL 约束避免模型偏离原来的 SFT 模型太远。

可以理解成：

```text
PPO：用奖励模型分数优化语言模型，但限制每次更新不要太激进
```

**GRPO（Group Relative Policy Optimization）** 可以理解成 PPO 类方法的一种变体。

它通常会对同一个问题采样多个回答，用组内相对得分来构造学习信号，从而减少对单独价值模型的依赖。

可以理解成：

```text
GRPO：让同一组回答相互比较，用相对好坏来优化策略
```

**DPO（Direct Preference Optimization）** 严格来说不是标准的在线强化学习。

它不需要显式训练奖励模型，也不需要像 PPO 那样让模型在线采样再通过奖励模型更新，而是直接用偏好数据训练模型更偏向被选中的回答。

可以理解成：

```text
DPO：直接用“哪个回答更好”的偏好数据优化模型，不显式跑在线 RL
```

三者可以简单对比：

| 方法 | 是否显式使用奖励模型 | 是否典型在线 RL | 核心思路 |
|---|---:|---:|---|
| PPO-RLHF | 通常使用 | 是 | 用奖励模型分数更新策略，并加 KL 约束 |
| GRPO | 可用规则或相对奖励 | 接近 RL 优化 | 用一组回答的相对好坏构造学习信号 |
| DPO | 不显式训练奖励模型 | 否 | 直接用偏好对优化模型 |

后面第 22 章会进一步展开这些方法的训练流程，并补充它们各自更适合的应用场景。

### 21.4 大模型 RL 和经典 RL 的区别

虽然大模型对齐借用了强化学习思想，但它和经典控制任务并不完全一样。

主要区别包括：

- 环境通常不是一个明确的物理世界或游戏模拟器，而是 prompt、用户反馈、奖励模型和数据分布组成的训练过程
- 动作空间极大，因为模型每一步都在整个词表上选择 token
- 奖励往往来自人类偏好或奖励模型，不一定是客观环境立即给出的分数
- 训练通常需要 KL 约束，避免模型为了追高奖励而破坏语言能力或偏离原始分布
- 很多方法使用离线偏好数据，不一定像经典 RL 那样持续在线探索环境

需要注意的是：

- 这些方法借用了强化学习思想
- 但工程实现通常比经典教科书例子复杂得多
- 像 DPO 这类方法常和 RLHF 一起讨论，但它并不是标准意义上的在线强化学习

### 21.5 经典 RL 概念在大模型训练中的映射

从经典强化学习视角出发，前面学过的很多核心概念，在大模型训练里都能找到相应映射：

```text
策略 πθ：语言模型本身
奖励 Reward：人类偏好、奖励模型分数、规则得分
Policy Gradient：提高高奖励回答的生成概率
KL 约束：限制新策略不要偏离原策略太远
Critic / Reward Model：提供评价信号
Actor-Critic：策略模型负责生成，评价模型负责打分
```

因此，打好 MDP、价值函数、策略梯度和 Actor-Critic 的基础，理解大模型强化学习会轻松很多。

## 22. 大模型偏好对齐与后训练：RLHF、RLAIF、DPO、GRPO/RLVR

前面的章节已经分别讲过：

- 第 14 章：策略优化算法本身，例如 PPO、Advantage、KL 约束
- 第 21 章：这些方法在大模型训练中的角色分工

本章把大模型偏好对齐和后训练方法集中展开，包括 **RLHF（Reinforcement Learning from Human Feedback）**、**RLAIF（Reinforcement Learning from AI Feedback）**、DPO、GRPO/RLVR 以及规则奖励。

这一章要回答的问题是：

> 大模型不是在游戏环境里移动，而是在生成文本。为什么还能用强化学习？奖励模型怎么训练？PPO 训练时为什么要同时维护多个模型？AI 反馈和规则奖励怎么进入训练？DPO 为什么能绕开显式 Reward Model？

### 22.1 RLHF（基于人类反馈的强化学习）概要

RLHF 的目标不是让模型继续预测下一个 token，而是让模型输出更符合人类偏好的回答。

可以把它放到大模型训练链路里：

```text
预训练 Pretraining
-> 监督微调 SFT
-> 奖励模型 Reward Model
-> PPO 策略优化
-> 对齐后的模型
```

其中：

- 预训练让模型学会语言和知识
- SFT 让模型学会按指令回答
- 奖励模型把人类偏好转成可优化的分数
- PPO 等策略优化方法让模型更倾向于生成高分回答

#### 22.1.1 RLHF 的背景、发展

纯语言模型训练目标通常是最大化下一个 token 的似然：

$$
\max_\theta
\sum_t
\log p_\theta(x_t \mid x_{<t})
$$

这个目标能让模型学会语言模式，但不能直接保证输出：

- 是否有帮助
- 是否遵循指令
- 是否安全
- 是否符合人类偏好
- 是否在复杂任务中给出更优答案

RLHF 的核心动机是：有些偏好很难写成明确标签，但人类可以比较两个回答哪个更好。

例如同一个 prompt 下：

```text
回答 A：更准确、更完整、更安全
回答 B：含糊、啰嗦、可能误导
```

人类不一定能给出精确分数，但可以标注：

```text
A 优于 B
```

RLHF 就把这类偏好比较转化成奖励模型，再用强化学习优化语言模型。

#### 22.1.2 语言模型的强化学习建模

把语言模型放进强化学习框架，可以这样对应：

| RL 概念 | 语言模型训练中的对应物 |
|---|---|
| Agent | 语言模型 |
| State / Observation | prompt、对话历史、已生成 token |
| Action | 下一个 token，或整段回答 |
| Policy | 当前语言模型 $\pi_\theta$ |
| Reward | 奖励模型分数、人类偏好、规则奖励 |
| Trajectory | prompt 后的一整段生成序列 |
| Episode | 一次完整问答或一次多轮对话 |

如果按 token 级动作建模：

```text
s_t = prompt + 已生成 token
a_t = 下一个 token
```

一次回答就是一条轨迹：

```text
prompt -> token1 -> token2 -> ... -> tokenT
```

但奖励通常不是每个 token 都有，而是在整段回答完成后给一个总分：

```text
answer 完成 -> Reward Model 打分 -> 得到 reward
```

这就是大模型 RL 比经典控制任务更特殊的地方：动作空间极大，奖励稀疏，而且奖励往往来自偏好模型而不是物理环境。

#### 22.1.3 RLHF 的训练样本、总流程

RLHF 常见数据包括三类。

第一类是 **SFT 数据**：

```text
prompt -> 高质量人工回答
```

用于训练初始指令模型。

第二类是 **偏好数据**：

```text
prompt
answer_chosen
answer_rejected
```

表示同一个 prompt 下，人类更偏好 `answer_chosen`。

第三类是 **RL 采样数据**：

```text
prompt
policy 生成的 answer
reward model 给出的分数
token logprob
value estimate
KL penalty
```

总流程可以写成：

```text
1. 用高质量指令数据训练 SFT 模型
2. 用 SFT 模型或多个模型生成候选回答
3. 人类标注回答偏好，形成 chosen / rejected 数据
4. 用偏好数据训练 Reward Model
5. 复制 SFT 模型作为 PPO 初始策略
6. 策略模型生成回答
7. Reward Model 打分
8. 加 KL 惩罚约束策略不要偏离参考模型
9. 用 PPO 更新策略模型
```

### 22.2 阶段一：图解奖励模型的设计与训练

奖励模型的作用是把“人类偏好”转成一个可优化的标量分数。

```text
prompt + answer
-> Reward Model
-> reward score
```

#### 22.2.1 奖励模型（Reward Model）的结构

奖励模型通常基于一个预训练语言模型或 SFT 模型初始化，然后在最后接一个标量输出头：

```text
Transformer Backbone
-> hidden states
-> scalar value head
-> reward score
```

结构可以理解成：

```text
输入 token:
    [prompt tokens, answer tokens]

Transformer:
    计算每个位置的 hidden state

Reward Head:
    取最后一个 token 或 EOS 位置 hidden state
    输出一个标量 reward
```

如果最后位置的 hidden state 是 $h_T$，奖励头可以写成：

$$
r_\phi(x, y)
=
w^\top h_T + b
$$

其中：

- $x$：prompt
- $y$：answer
- $\phi$：奖励模型参数
- $r_\phi(x,y)$：奖励模型给出的标量分数

#### 22.2.2 奖励模型的输入与奖励分数

奖励模型的输入通常是完整的 prompt-answer 序列：

```text
User prompt:
    请解释 PPO 的核心思想

Assistant answer:
    PPO 通过限制新旧策略差异来稳定策略优化...
```

奖励模型输出一个标量：

```text
reward = 2.7
```

这个分数不是绝对真理，而是模型学到的偏好估计：

```text
分数高：更像人类偏好的回答
分数低：更不像人类偏好的回答
```

训练奖励模型时，绝对分数本身不重要，重要的是相对排序：

```text
r(prompt, chosen) > r(prompt, rejected)
```

#### 22.2.3 奖励模型的 Loss 解析

奖励模型常用 pairwise ranking loss。

给定一条偏好样本：

```text
(x, y_w, y_l)
```

其中：

- $x$：prompt
- $y_w$：winner / chosen answer
- $y_l$：loser / rejected answer

奖励模型分别打分：

$$
r_w = r_\phi(x, y_w)
$$

$$
r_l = r_\phi(x, y_l)
$$

希望 $r_w$ 大于 $r_l$。常见 loss 是：

$$
\mathcal{L}_{RM}
=
-
\log
\sigma
\left(
r_w - r_l
\right)
$$

其中 $\sigma$ 是 sigmoid 函数。

如果 $r_w - r_l$ 很大：

```text
模型已经认为 chosen 明显更好
-> loss 很小
```

如果 $r_w - r_l$ 很小或为负：

```text
模型没区分出 chosen 更好
-> loss 变大
```

batch 形式可以写成：

$$
\mathcal{L}_{RM}
=
-
\frac{1}{B}
\sum_{i=1}^{B}
\log
\sigma
\left(
r_\phi(x_i, y_{w,i})
-
r_\phi(x_i, y_{l,i})
\right)
$$

#### 22.2.4 奖励模型训练全景图

奖励模型训练流程：

```text
Prompt 集合
  |
  v
多个候选回答
  |
  v
人类偏好标注
  |
  v
(prompt, chosen, rejected)
  |
  v
Reward Model 分别打分
  |
  v
r_chosen - r_rejected
  |
  v
Pairwise ranking loss
  |
  v
更新 Reward Model
```

训练完成后，奖励模型会被冻结或半冻结，用来给 PPO 阶段的策略模型生成奖励。

需要注意：

```text
奖励模型不是最终回答模型
它只是给回答打分的评价器
```

#### 22.2.5 奖励模型的 Scaling Law

奖励模型通常也会受模型规模、数据规模和标注质量影响。

可以先抓住几个经验规律：

- 奖励模型越强，通常越能分辨细微偏好差异
- 偏好数据越多，奖励模型排序能力通常越稳定
- 标注一致性越高，奖励模型越容易学习
- 训练分布和 PPO 生成分布越接近，奖励越可靠

但奖励模型也会有上限和风险。

第一，奖励模型可能学到标注偏差：

```text
标注者偏好冗长回答
-> 奖励模型偏好冗长回答
-> 策略模型学会无意义扩写
```

第二，策略模型可能过度优化奖励模型：

```text
Reward Model 只是偏好近似器
PPO 反复优化它
-> 策略找到奖励模型漏洞
-> reward 上升，但真实人类满意度下降
```

这就是后面要讲的 reward hacking。

### 22.3 阶段二：多模型联动的 PPO 训练

RLHF 的 PPO 阶段不是一个模型单独训练，而是多个模型联动。

最常见会看到四类模型：

```text
Policy Model
Reference Model
Reward Model
Value Model
```

#### 22.3.1 四种模型的角色图解

四种模型的角色如下：

| 模型 | 是否生成回答 | 是否训练更新 | 作用 |
|---|---:|---:|---|
| Policy Model | 是 | 是 | 当前要优化的策略模型 |
| Reference Model | 否 | 否 | 提供 KL 约束基准 |
| Reward Model | 否 | 通常冻结 | 给完整回答打奖励分 |
| Value Model | 否 | 是 | 估计状态价值，用于 PPO / GAE |

图解：

```text
prompt
  |
  v
Policy Model 生成 answer
  |
  +--> Reward Model 打分：r_rm
  |
  +--> Reference Model 计算 logprob_ref
  |
  +--> Policy Model 计算 logprob_policy
  |
  +--> Value Model 估计 V
  |
  v
reward = r_rm - beta * KL(policy || reference)
  |
  v
PPO 更新 Policy Model 和 Value Model
```

#### 22.3.2 各模型的结构、初始化、实践技巧

**Policy Model** 通常从 SFT 模型初始化：

```text
policy_init = SFT model
```

它是最终要得到的模型，训练中会被 PPO 更新。

**Reference Model** 通常也是 SFT 模型的一份冻结副本：

```text
reference = copy(SFT model)
freeze(reference)
```

它用来计算 KL 惩罚，防止策略模型偏离 SFT 模型太远。

**Reward Model** 可以从 SFT 模型或预训练模型初始化，再用偏好数据训练：

```text
reward_model = backbone + scalar head
train(reward_model, preference_pairs)
freeze(reward_model)
```

**Value Model** 有两种常见实现：

```text
方案 A：Policy backbone 上加 value head
方案 B：单独训练一个 value model
```

工程上常把 policy 和 value head 放在同一个模型骨干上，节省显存和计算。

实践技巧：

- Reference Model 必须冻结
- Reward Model 在 PPO 阶段通常冻结
- Policy 和 Value 可以共享 backbone，但 loss 要分清
- 需要记录旧策略 logprob，PPO ratio 依赖它
- 需要限制 response 长度，避免模型通过冗长输出刷奖励

#### 22.3.3 各模型的输入、输出

| 模型 | 输入 | 输出 |
|---|---|---|
| Policy Model | prompt + 已生成 token | 下一个 token 分布、生成 answer |
| Reference Model | prompt + answer | reference logprob |
| Reward Model | prompt + answer | scalar reward |
| Value Model | prompt + partial answer | value estimate |

一次 rollout 中常保存：

```text
prompt
response tokens
policy logprobs
reference logprobs
values
reward score
attention mask
done / eos
```

这些数据会被整理成 PPO batch，用于计算：

- KL penalty
- final reward
- returns
- advantages
- policy loss
- value loss

#### 22.3.4 基于 KL 散度的策略约束

RLHF 中最重要的约束之一是：新策略不要偏离参考模型太远。

大模型对齐里使用 KL 散度，核心原因是：**Reward Model 只是真实人类偏好的近似，不能让策略模型无限追求 reward 分数。**

如果只最大化奖励模型分数，模型可能学到一些投机行为：

```text
奖励模型偏好详细回答
-> 策略模型把回答越写越长
-> reward score 上升
-> 但真实用户体验可能变差
```

也可能出现：

- 语言能力退化，输出变得不自然
- 回答模式塌缩，总是使用固定套话
- 为了安全分数过度拒答
- 利用 Reward Model 的漏洞，让 reward 上升但真实质量下降

因此 RLHF 通常不是只优化：

```text
让 reward 越高越好
```

而是优化：

```text
让回答更符合偏好
同时不要离原来的 SFT 模型太远
```

这里的参考模型 $\pi_{ref}$ 通常是冻结的 SFT 模型。它保留了预训练和监督微调阶段学到的语言能力、指令跟随能力和基本行为分布。KL 惩罚相当于提醒策略模型：

```text
可以朝人类偏好方向调整
但不要为了拿高 reward 突然偏离原始语言模型太远
```

token 级 KL 可以近似写成：

$$
KL_t
\approx
\log \pi_\theta(a_t \mid s_t)
-
\log \pi_{ref}(a_t \mid s_t)
$$

常见 reward shaping 是：

$$
r_t
=
r_t^{task}
-
\beta KL_t
$$

在很多 RLHF 实现中，奖励模型只在回答结束时给一个最终奖励：

```text
中间 token reward：- beta * KL_t
最后 token reward：reward_model_score - beta * KL_t
```

这样做的直觉是：

```text
Reward Model 鼓励回答更符合偏好
KL penalty 防止模型为了高 reward 偏离原始语言模型太远
```

$\beta$ 是 KL 惩罚系数：

- $\beta$ 太小：策略可能过度追求 reward，出现 reward hacking
- $\beta$ 太大：策略更新太保守，学不到明显改进

#### 22.3.5 基于 PPO 的 RLHF 核心实现

PPO-RLHF 的核心仍然是 PPO-Clip。

首先保存旧策略生成时的 log probability：

$$
\log \pi_{old}(a_t \mid s_t)
$$

更新时用当前策略重新计算：

$$
\log \pi_{\theta}(a_t \mid s_t)
$$

ratio 是：

$$
\rho_t(\theta)
=
\exp
\left(
\log \pi_\theta(a_t \mid s_t)
-
\log \pi_{old}(a_t \mid s_t)
\right)
$$

PPO policy loss：

$$
L^{CLIP}
=
\mathbb{E}
\left[
\min
\left(
\rho_t \hat{A}_t,
\operatorname{clip}(\rho_t, 1-\epsilon, 1+\epsilon)\hat{A}_t
\right)
\right]
$$

训练时通常最小化：

$$
\mathcal{L}_{policy}
=
-
L^{CLIP}
$$

Value loss：

$$
\mathcal{L}_{value}
=
\frac{1}{2}
\left(
V_\psi(s_t)
-
R_t^{target}
\right)^2
$$

总 loss：

$$
\mathcal{L}
=
\mathcal{L}_{policy}
+
c_v \mathcal{L}_{value}
-
c_e \mathcal{H}
$$

其中 $\mathcal{H}$ 是策略熵，用来保留一定探索性。

#### 22.3.6 全景图：基于 PPO 的训练

完整训练闭环：

```text
Prompt batch
  |
  v
Policy Model 生成 responses
  |
  v
保存 response token、old_logprob、value
  |
  +--> Reward Model: 得到 reward score
  |
  +--> Reference Model: 得到 ref_logprob
  |
  v
计算 KL penalty
  |
  v
构造 token-level rewards
  |
  v
计算 returns 和 GAE advantages
  |
  v
PPO mini-batch 多轮更新
  |
  +--> 更新 Policy
  |
  +--> 更新 Value
  |
  v
进入下一轮 rollout
```

最关键的工程点：

```text
rollout 阶段：生成数据，保存 old_logprob
training 阶段：重新计算 new_logprob，做 PPO 更新
reference / reward 模型：提供约束和奖励，一般不更新
```

### 22.4 RLHF 实践技巧

RLHF 的难点不只是公式，而是训练很容易被奖励模型、KL、采样分布和超参数影响。

#### 22.4.1 奖励欺骗（Reward Hacking）

Reward Hacking 指的是：模型学会提高奖励模型分数，但真实质量没有提升，甚至变差。

常见表现：

- 回答变得过长，但信息密度下降
- 使用奖励模型偏好的固定格式套话
- 回避困难问题以获得安全高分
- 编造看似合理但不可验证的内容
- 在某些 prompt 上利用奖励模型漏洞

根本原因是：

```text
Reward Model 只是人类偏好的近似
策略优化会放大奖励模型的漏洞
```

缓解方式：

- 控制 PPO 更新强度和 KL
- 定期做人类评估
- 更新奖励模型数据分布
- 加入规则约束或安全过滤
- 监控 reward 与真实偏好是否脱钩

#### 22.4.2 拒绝采样（Rejection Sampling）微调

拒绝采样微调是一种比 PPO 简单的偏好优化方式。

流程是：

```text
1. 对每个 prompt 采样多个回答
2. 用 Reward Model 给每个回答打分
3. 选出分数最高或满足条件的回答
4. 把这些回答当成新的 SFT 数据
5. 继续监督微调模型
```

它不需要在线 PPO，也不需要 value model。

优点：

- 工程简单
- 训练稳定
- 容易复用 SFT 训练管线

缺点：

- 依赖采样质量
- 不能像 PPO 那样直接用 token-level policy gradient 优化
- 仍可能继承奖励模型偏差

一句话：

```text
拒绝采样微调 = 用奖励模型筛数据，再做监督学习。
```

#### 22.4.3 强化学习与 RLHF 的训练框架

经典 RL 训练框架：

```text
Agent
-> 在环境中动作
-> 环境返回 reward 和 next state
-> 算法更新策略
```

RLHF 训练框架：

```text
Policy Model
-> 对 prompt 生成回答
-> Reward Model / Rule / Human Feedback 给分
-> KL 约束参考模型
-> PPO / GRPO / DPO 等方法更新模型
```

主要差异：

| 对比项 | 经典 RL | RLHF |
|---|---|---|
| 环境 | 游戏、机器人、仿真器 | prompt 分布、奖励模型、人类偏好 |
| 动作 | 离散动作或连续控制量 | token 或完整回答 |
| 奖励 | 环境直接给出 | 人类偏好、奖励模型、规则 |
| 安全约束 | 任务环境约束 | KL、拒答规则、安全策略 |
| 评估 | episode return | 人类偏好胜率、reward、KL、任务指标 |

#### 22.4.4 RLHF 的超参数

常见超参数包括：

| 超参数 | 作用 | 过小 | 过大 |
|---|---|---|---|
| learning rate | 控制更新速度 | 学得慢 | 容易不稳定 |
| batch size | 控制梯度估计稳定性 | 噪声大 | 资源占用高 |
| rollout length | 每次采样长度 | 信息少 | 训练成本高 |
| PPO epochs | 同一批数据复用次数 | 利用不足 | 过拟合旧数据 |
| clip range | 限制 ratio 变化 | 更新太保守 | 策略漂移 |
| KL coefficient $\beta$ | 限制偏离参考模型 | reward hacking 风险高 | 学不到偏好改进 |
| value loss coef | value loss 权重 | Critic 不准 | 压制 policy 更新 |
| entropy coef | 探索强度 | 策略过早收缩 | 输出不稳定 |
| max response length | 输出长度上限 | 回答不完整 | 成本高、易刷长度 |

RLHF 调参通常要同时看 reward、KL、人工评估和输出样例，而不能只看单个 loss。

#### 22.4.5 RLHF 的关键监控指标

训练中常见监控指标：

| 指标 | 含义 | 风险信号 |
|---|---|---|
| reward model score | 奖励模型评分 | 分数涨但人工质量不涨 |
| KL to reference | 策略偏离参考模型程度 | KL 过大表示漂移，过小表示学不动 |
| policy loss | PPO 策略损失 | 剧烈震荡可能训练不稳 |
| value loss | Critic 误差 | 长期过高说明 value 学不好 |
| entropy | 策略随机性 | 太低可能模式塌缩 |
| clip fraction | ratio 被裁剪比例 | 太高说明更新过猛 |
| response length | 回答长度 | 异常增长可能在刷奖励 |
| win rate | 人类或 AI 偏好胜率 | 和 reward 脱钩要警惕 |
| refusal rate | 拒答比例 | 过高可能过度保守 |
| toxicity / safety metrics | 安全指标 | 必须和 reward 一起看 |

一个重要原则：

```text
Reward 上升不等于模型真的更好。
必须结合人工评估、任务指标和样例审查。
```

### 22.5 基于 AI 反馈的强化学习

RLAIF（Reinforcement Learning from AI Feedback）用 AI 模型提供一部分偏好反馈或奖励信号，减少对人工标注的依赖。

它不是完全否定人类反馈，而是把反馈来源从“只依赖人类”扩展为：

```text
人类反馈 + AI 反馈 + 规则反馈
```

#### 22.5.1 RLAIF 的原理图解

RLAIF 的基本流程：

```text
Prompt
  |
  v
模型生成多个回答
  |
  v
AI Evaluator 比较回答或打分
  |
  v
形成偏好数据 / 奖励分数
  |
  v
训练 Reward Model 或直接构造奖励
  |
  v
PPO / GRPO / DPO 等方法优化策略模型
```

AI 反馈可以有几种形式：

| 形式 | 例子 |
|---|---|
| AI preference | AI 判断 A 回答优于 B 回答 |
| AI critique | AI 给出问题点和修改建议 |
| AI score | AI 按 rubric 给出 1-5 分 |
| AI rule check | AI 判断是否违反某条规则 |

RLAIF 的优点：

- 标注成本低
- 反馈速度快
- 可以覆盖大量 prompt
- 适合有明确评价标准的任务

风险：

- AI 评审模型本身可能有偏差
- 反馈质量受 evaluator 能力限制
- 可能放大 evaluator 的偏好或错误
- 仍需要人类抽检和安全校准

#### 22.5.2 CAI：基于宪法的强化学习

CAI（Constitutional AI）是一种典型 RLAIF 思路。

它先定义一组原则，称为 constitution：

```text
回答应该有帮助
回答不应鼓励伤害
回答应尊重隐私
回答遇到危险请求时应安全拒绝
回答应尽量诚实、不编造
```

训练流程可以概括为两个阶段。

第一阶段是监督式自我修正：

```text
模型生成初始回答
-> 根据 constitution 自我 critique
-> 根据 critique 改写回答
-> 用改写后的回答做监督微调
```

第二阶段是 AI 反馈偏好优化：

```text
同一 prompt 生成多个回答
-> AI 根据 constitution 比较哪个更符合原则
-> 形成偏好数据
-> 训练偏好模型或奖励模型
-> 用 RL 方法优化策略
```

CAI 的关键点是：评价标准不是完全隐含在标注者偏好里，而是显式写成一组原则。

它的优势：

- 可以减少部分人工偏好标注成本
- 原则更可审查
- 适合安全、拒答、价值边界等任务

它的风险：

- constitution 写得不好会直接影响模型行为
- 原则之间可能冲突
- AI critique 和 AI preference 仍需要质量控制

#### 22.5.3 RBR：基于规则的奖励

RBR（Rule-Based Rewards）指用明确规则构造奖励信号。

它适合那些能被程序、测试、正则、分类器或验证器判断的任务。

例如：

```text
代码题：
    单元测试通过 -> +1
    编译失败 -> -1

数学题：
    最终答案正确 -> +1
    格式错误 -> -0.2

安全任务：
    泄露隐私 -> -1
    正确拒绝危险请求 -> +1

格式任务：
    输出合法 JSON -> +0.5
    JSON 解析失败 -> -0.5
```

RBR 的优点：

- 成本低
- 可重复
- 标准清晰
- 适合自动化大规模训练

RBR 的局限：

- 规则覆盖不到的质量维度无法评价
- 规则写得过窄会导致模型钻空子
- 规则之间可能冲突
- 对开放式问答、创意写作等任务不够充分

RBR 常和 RLHF / RLAIF 组合使用：

```text
最终奖励 =
    奖励模型分数
  + AI 评审分数
  + 规则奖励
  - KL 惩罚
  - 安全惩罚
```

也可以写成：

$$
R_{total}
=
w_1 R_{RM}
+
w_2 R_{AI}
+
w_3 R_{rule}
-
\beta KL(\pi_\theta \parallel \pi_{ref})
$$

其中 $w_1, w_2, w_3$ 控制不同奖励来源的权重。

最短理解：

```text
RLHF：人类给偏好
RLAIF：AI 给偏好或评价
CAI：AI 按显式原则给反馈
RBR：规则或验证器直接给奖励
```

如果规则奖励来自可自动验证的答案、测试或程序检查，这类训练在大模型推理语境中也常被称为 **RLVR（Reinforcement Learning with Verifiable Rewards，基于可验证奖励的强化学习）**。

### 22.6 GRPO 与 RLVR：面向可验证任务的强化学习

GRPO（Group Relative Policy Optimization，组相对策略优化）可以看成 PPO 类方法在大模型推理任务中的一种变体。

速记：

> 不单独训练一个 value model，而是对同一个 prompt 采样多条回答，用组内相对分数构造 Advantage。

更短地说：

```text
GRPO = 同题多答 + 组内比较 + PPO-Clip 更新 + KL 约束
RLVR = 用规则、测试、标准答案等可验证信号提供 reward
```

GRPO 描述的是优化算法，RLVR 描述的是奖励来源。数学题、代码题、工具调用、格式约束等任务可以自动判断结果是否正确，因此常把 RLVR 和 GRPO 组合使用。

#### 22.6.1 GRPO 的提出背景与意义

GRPO 最早来自 DeepSeek 公司 2024 年 2 月发表的论文：[DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models](https://arxiv.org/abs/2402.03300)。这篇论文报告了 DeepSeekMath 7B 在数学推理上的结果：GSM8K 88.2%，MATH 51.7%，在开源 7B 数学模型中具有代表性。

更重要的是，这篇论文首次提出了 **GRPO（Group Relative Policy Optimization）**：

```text
PPO：需要 value model / critic 来估计 Advantage
GRPO：移除 value model / critic，用组内归一化奖励估计 Advantage
```

这个改动的意义在于：推理模型训练经常需要对同一个问题采样多条答案，再根据答案正确性、测试结果或规则奖励进行比较。GRPO 把这种“同题多答、组内比较”的结构直接写进策略优化目标，降低了 PPO 式 RLHF 中 value model 的训练和显存成本。

后来 DeepSeek-R1 / DeepSeek-R1-Zero 继续使用 GRPO 进行大规模推理强化学习，进一步放大了 GRPO 的影响。可以说，GRPO 定义了 2024 之后开源 reasoning model 中一条非常重要的 RL 训练范式；后续 DAPO、Dr.GRPO、GSPO 等方法，也是在 GRPO 暴露出的稳定性、长度偏置、token-level ratio 等问题上继续改进。

> 本节主要参考 DeepSeekMath 论文和 Hugging Face TRL 的 GRPOTrainer 文档。DeepSeekMath 提出了 GRPO；TRL 文档则把 GRPO 拆成生成 completions、计算 advantage、估计 KL、计算 loss 四个工程步骤。

#### 22.6.2 GRPO 要解决什么问题

标准 PPO-RLHF 的训练链路通常比较重：

```text
Policy Model 生成回答
-> Reward Model 打分
-> Value Model / Critic 估计 Advantage
-> PPO-Clip 更新 Policy Model
-> KL 约束限制偏离 Reference Model
```

这条链路里，Value Model 的作用是估计“当前回答比预期好多少”。在大模型推理任务中，很多题目可以直接打分，例如数学答案是否正确、代码是否通过单元测试、工具调用参数是否符合规则。此时可以对同一个 prompt 采样多条回答，把这一组回答的平均奖励当作基准，再用每条回答相对组内平均的高低构造 Advantage。

这就是 GRPO 的核心思路：

```text
PPO：用 Value Model 估计 Advantage
GRPO：用同一 prompt 下多条回答的组内相对奖励估计 Advantage
```

这样可以减少单独训练 Value Model 的成本，也更贴合“同一道题多次作答、从结果好坏中学习”的推理训练场景。

#### 22.6.3 样本结构与奖励来源

GRPO 的基本训练样本可以写成：

```text
prompt x
+ 一组回答 y_1, y_2, ..., y_G
+ 每条回答对应的 reward r_1, r_2, ..., r_G
```

其中 $G$ 表示同一个 prompt 下采样的回答数量。回答通常来自当前策略的旧版本 $\pi_{\theta_{old}}$：

$$
\{y_i\}_{i=1}^{G}
\sim
\pi_{\theta_{old}}(\cdot \mid x)
$$

每条回答通过奖励函数 $R$ 得到分数：

$$
r_i
=
R(x, y_i)
$$

在 RLVR 场景中，奖励可以来自可自动验证的规则：

| 任务类型 | 可验证奖励示例 | 奖励含义 |
|---|---|---|
| 数学题 | 最终答案是否等于标准答案 | 答对给高分，答错给低分 |
| 代码题 | 是否通过单元测试 | 测试通过越多，奖励越高 |
| 工具调用 | 参数、函数名、调用顺序是否正确 | 调用合法且结果正确给高分 |
| 格式约束 | 是否满足 JSON、XML、指定字段格式 | 格式正确给奖励，格式错误扣分 |
| 多步推理 | 最终答案、关键中间步骤是否可检查 | 结果正确且过程合规给更高分 |

需要注意：可验证奖励通常更关注“结果是否正确”，不一定能完整衡量表达质量、解释清晰度和安全边界。因此生产训练中经常把规则奖励、格式奖励、安全过滤和人工 / AI 评估结合使用。

#### 22.6.4 组内相对 Advantage

对同一个 prompt $x$，假设采样得到 $G$ 条回答：

```text
y_1, y_2, ..., y_G
```

然后用奖励函数或规则打分：

```text
r_1, r_2, ..., r_G
```

先计算组内平均奖励：

$$
\mu_r
=
\frac{1}{G}
\sum_{i=1}^{G}
r_i
$$

再计算组内标准差：

$$
\sigma_r
=
\sqrt{
\frac{1}{G}
\sum_{i=1}^{G}
(r_i - \mu_r)^2
}
$$

然后用组内归一化奖励构造 Advantage：

$$
\hat{A}_i
=
\frac{
r_i - \mu_r
}{
\sigma_r + \delta
}
$$

这表示：

```text
同一个 prompt 下，奖励高于组内平均 -> 正优势 -> 提高生成概率
同一个 prompt 下，奖励低于组内平均 -> 负优势 -> 降低生成概率
接近组内平均 -> 优势接近 0 -> 更新信号较弱
```

$\delta$ 是一个很小的平滑项，用来避免标准差接近 0 时数值不稳定。

举一个直观例子：

```text
同一道数学题采样 4 个回答，奖励分别是：
1, 1, 0, 0

组内平均奖励 = 0.5
答对的回答高于平均，得到正 Advantage
答错的回答低于平均，得到负 Advantage
```

如果一组回答全错或全对，组内差异会很小，训练信号也会变弱。这时需要改进采样、多样性、题目难度或奖励设计。

#### 22.6.5 GRPO Loss：PPO-Clip + KL

GRPO 仍然使用 PPO-Clip 风格的策略更新。先定义当前策略和旧策略之间的概率比：

$$
\rho_i(\theta)
=
\frac{
\pi_\theta(y_i \mid x)
}{
\pi_{\theta_{old}}(y_i \mid x)
}
$$

在语言模型里，整段回答的 log probability 通常按 token 累加：

$$
\log \pi_\theta(y_i \mid x)
=
\sum_{t=1}^{T_i}
\log
\pi_\theta
\left(
y_{i,t}
\mid
x, y_{i,<t}
\right)
$$

其中 $T_i$ 是第 $i$ 条回答的 token 数量。

简化写法下，GRPO 的优化目标可以表示为：

$$
J_{GRPO}(\theta)
=
\mathbb{E}
\left[
\frac{1}{G}
\sum_{i=1}^{G}
\min
\left(
\rho_i(\theta)\hat{A}_i,
\operatorname{clip}
(\rho_i(\theta), 1-\epsilon, 1+\epsilon)
\hat{A}_i
\right)
-
\beta
D_{KL}
(\pi_\theta \parallel \pi_{ref})
\right]
$$

这里写的是需要最大化的目标 $J_{GRPO}$。工程代码里通常把它取负，作为 loss 最小化。

其中：

- $\rho_i(\theta)$：当前策略相对旧策略生成回答 $y_i$ 的概率变化
- $\hat{A}_i$：第 $i$ 条回答的组内相对 Advantage
- $\epsilon$：clip 范围，限制单次策略更新幅度
- $\pi_{ref}$：冻结的参考模型，通常来自 SFT 模型
- $\beta$：KL 约束强度，控制策略偏离参考模型的程度

从优化方向看：

```text
正 Advantage 的回答：提高生成概率
负 Advantage 的回答：降低生成概率
clip：限制更新幅度，避免策略一步变化过大
KL：限制模型偏离参考模型太远，保留原有语言能力和安全边界
```

GRPO 论文中还使用了一种 KL 近似项，常见写法是：

$$
D_{KL}
\left[
\pi_\theta
\parallel
\pi_{ref}
\right]
\approx
\frac{
\pi_{ref}(y_i \mid x)
}{
\pi_\theta(y_i \mid x)
}
-
\log
\frac{
\pi_{ref}(y_i \mid x)
}{
\pi_\theta(y_i \mid x)
}
-
1
$$

实际工程实现通常按 token 计算 log probability、ratio、clip loss 和 KL，再对 response token 做平均或求和。

#### 22.6.6 GRPO 训练流程

GRPO 的训练流程：

```text
1. 准备一批 prompt
2. 用旧策略 pi_old 对每个 prompt 采样 G 条回答
3. 用规则、测试、标准答案或奖励模型给每条回答打分
4. 对同一个 prompt 内的奖励做均值、标准差归一化
5. 得到每条回答的组内相对 Advantage
6. 计算当前策略 pi_theta 的 response logprob
7. 计算旧策略 pi_old 的 response logprob
8. 计算参考模型 pi_ref 的 response logprob
9. 用 PPO-Clip 目标和 KL 约束更新 pi_theta
10. 周期性刷新 pi_old，继续下一轮采样和训练
```

可以画成：

```text
Prompt x
  |
  v
Policy / Old Policy 采样 G 条回答
  |
  v
y_1, y_2, ..., y_G
  |
  v
规则 / 测试 / 标准答案 / Reward Model 打分
  |
  v
r_1, r_2, ..., r_G
  |
  v
组内归一化，得到 A_1, A_2, ..., A_G
  |
  v
PPO-Clip + KL
  |
  v
更新 Policy Model
```

#### 22.6.7 GRPO、PPO-RLHF、DPO 的区别

| 对比项 | PPO-RLHF | GRPO / RLVR | DPO |
|---|---|---|---|
| 训练信号 | Reward Model 输出标量奖励 | 规则、测试、标准答案或奖励函数 | chosen / rejected 偏好对 |
| 数据形态 | 在线采样回答，再打 reward | 同一 prompt 下采样一组回答，再组内比较 | 离线偏好数据 |
| Advantage 来源 | Value Model / Critic / GAE | 组内归一化奖励 | 不显式使用 Advantage |
| Value Model | 通常需要 | 通常不需要 | 不需要 |
| Reward Model | 通常需要 | 可用规则奖励，也可混合奖励模型 | 不显式训练 Reward Model |
| Reference Model / KL | 常用 KL 约束 | 常用 KL 约束 | 通过参考模型 logprob 进入 DPO loss |
| 适合场景 | 开放式偏好对齐、复杂 reward | 数学、代码、工具调用等可验证任务 | 偏好对明确、希望训练链路更轻的场景 |

一句话理解：

```text
PPO-RLHF：用奖励模型和 Value Model 做在线策略优化
GRPO/RLVR：用同题多答的相对奖励做推理强化训练
DPO：用 chosen / rejected 偏好对直接优化策略模型
```

#### 22.6.8 实践注意点

1. 奖励函数决定训练方向。规则奖励写得不完整，模型可能学会钻规则空子，例如只输出格式正确但内容无效的答案。

2. 组大小 $G$ 会影响 Advantage 质量。$G$ 太小，组内均值和标准差不稳定；$G$ 太大，采样和训练成本会上升。

3. 采样温度会影响组内差异。温度太低，一组回答过于相似；温度太高，回答质量可能整体下降。

4. $\beta$ 控制 KL 约束强度。$\beta$ 较大时模型更贴近参考模型，更新更保守；$\beta$ 较小时模型更容易追逐奖励，但偏离和奖励投机风险更高。

5. 题目难度要有区分度。如果大部分样本全对或全错，组内相对奖励提供的学习信号会变弱。

6. 只用结果奖励可能忽略过程质量。数学和代码任务可以加入格式、步骤、可执行性、安全性等辅助奖励，但权重要控制，避免模型只优化表面格式。

7. 训练效果不能只看 reward。还要评估正确率、pass@k、输出长度、重复率、拒答率、安全指标和通用能力回退。


### 22.7 方法选型：DPO、PPO/RLHF、GRPO/RLVR 适合什么场景

这些方法都在做大模型后训练，但适合的任务类型不同。最短判断方式是：

```text
DPO：有“好回答 / 差回答”偏好对
PPO/RLHF：需要奖励模型持续评价开放式回答
GRPO/RLVR：答案能被规则、测试或标准答案自动验证
```

训练架构和公式细节放在各自专题里：PPO-RLHF 见第 22.3 节，GRPO/RLVR 见第 22.6 节，DPO 见第 22.8 节。这里先只做工程选型。

先看最短对比：

| 对比项 | RLHF + PPO | DPO |
|---|---|---|
| 偏好数据怎么用 | 先训练 Reward Model，再用 PPO 优化策略 | 直接用 chosen / rejected 优化策略 |
| 是否需要 Reward Model | 需要 | 不需要显式奖励模型 |
| 是否需要在线 rollout | 需要 Policy Model 生成新回答 | 不需要 PPO 式在线 rollout |
| 是否需要 Value Model | 通常需要 | 不需要 |
| Reference Model 的作用 | 计算 KL 惩罚，防止策略跑偏 | 作为偏移基准，约束偏好优化不要过度偏离 SFT |
| 工程复杂度 | 高，多模型联动 | 低，更接近监督式偏好训练 |

#### 22.7.1 DPO：适合偏好对明确的场景

DPO 直接使用偏好数据：

```text
prompt + chosen response + rejected response
```

它不需要显式训练奖励模型，也不需要在线 PPO rollout。只要能构造“哪个回答更好”的数据，就可以用 DPO 做偏好优化。

DPO 的训练直觉是：

```text
1. 提高当前模型相对 reference model 生成 chosen 的概率
2. 降低当前模型相对 reference model 生成 rejected 的概率
```

完整的隐式奖励、DPO loss、数据构建和训练流程见第 22.8 节。

典型场景：

| 场景 | 训练信号 | 为什么适合 DPO |
|---|---|---|
| 聊天助手风格优化 | 更自然、更有帮助的回答作为 chosen | 主观质量可以通过人工或 AI 比较 |
| 客服话术优化 | 规范回答优于生硬或不完整回答 | 企业通常能整理标准话术和反例 |
| 安全对齐 | 安全回答优于危险回答 | 可以把拒答、改写、解释做成偏好对 |
| RAG 回答优化 | 忠实资料的回答优于幻觉回答 | 可以用检索证据构造 chosen/rejected |
| 产品语气调整 | 专业、简洁、礼貌的回答作为 chosen | 风格偏好比绝对分数更容易标注 |

一句话：

```text
DPO 适合“我能告诉模型 A 比 B 好，但不一定能给 A 打几分”的场景。
```

#### 22.7.2 PPO/RLHF：适合开放式人类偏好场景

PPO/RLHF 的典型流程是：

```text
人类偏好数据
-> 训练 Reward Model
-> 模型在线生成回答
-> Reward Model 给分
-> PPO 根据奖励更新策略
```

它适合质量标准复杂、很难用简单规则判断的开放式任务。

典型场景：

| 场景 | 奖励来源 | 为什么适合 PPO/RLHF |
|---|---|---|
| 通用聊天助手 | 奖励模型学习人类偏好 | 有帮助性、诚实性、礼貌性很难写成固定规则 |
| 长文本回答优化 | 人类偏好训练出的 reward | 结构、完整性、可读性需要综合评价 |
| 安全与无害性训练 | 人类安全偏好或安全 reward | 拒答是否合理常依赖语境 |
| 复杂指令遵循 | Reward Model 判断是否满足指令 | 开放式任务不能只看标准答案 |
| 多目标对齐 | helpful、harmless、honest 等综合 reward | 多个偏好目标需要统一成可优化信号 |

PPO/RLHF 的优势是表达能力强，能处理复杂偏好；代价是训练系统更重，通常要维护 Policy Model、Reference Model、Reward Model 和 Value Model。

一句话：

```text
PPO/RLHF 适合“开放式回答质量很复杂，需要奖励模型持续打分”的场景。
```

#### 22.7.3 GRPO/RLVR：适合可验证正确性的场景

GRPO/RLVR 常用于推理模型训练。它通常对同一个 prompt 采样多个回答，然后用验证器、规则或标准答案打分，再根据组内相对好坏更新模型。

典型流程：

```text
同一问题采样多个回答
-> 验证器给出 reward
-> 组内比较得到 advantage
-> GRPO 更新策略模型
```

典型场景：

| 场景 | 可验证奖励 | 为什么适合 GRPO/RLVR |
|---|---|---|
| 数学推理 | 最终答案是否等于标准答案 | 对错可以自动检查 |
| 代码生成 | 单元测试是否通过 | 测试结果能直接作为 reward |
| SQL 生成 | 查询结果是否正确 | 可以执行 SQL 并比较结果 |
| 工具调用 | 参数格式、调用结果是否正确 | 工具调用链路可程序化校验 |
| 选择题/判断题 | 选项是否正确 | 标准答案明确 |
| 逻辑与规则任务 | 是否满足约束条件 | 规则检查器能给出奖励 |

GRPO/RLVR 的重点不是让回答“看起来更讨人喜欢”，而是让模型更会做能被验证的任务，尤其是数学、代码、工具调用和复杂推理。

一句话：

```text
GRPO/RLVR 适合“答案能自动判对错，模型可以多试几次再从奖励中学习”的场景。
```

#### 22.7.4 一个实用选择表

工程上可以按下面方式选择：

| 你的问题 | 更适合的方法 | 原因 |
|---|---|---|
| 我有 chosen/rejected 偏好数据 | DPO | 直接偏好优化，工程简单 |
| 我想让模型更符合人类主观偏好 | RLHF + PPO | 奖励模型能学习复杂偏好 |
| 我想提升数学、代码、工具调用能力 | RLVR + GRPO | 结果可验证，适合用规则奖励 |
| 我想降低人工标注成本 | RLAIF + DPO/GRPO/PPO | 用 AI 评审构造偏好或奖励 |
| 我只想先做一个低成本后训练实验 | SFT + DPO | 不需要搭完整 RLHF 系统 |
| 我需要训练强推理模型 | SFT + RLVR + GRPO | 能利用大量可验证题目做强化学习 |

把它们和前面经典强化学习算法联系起来：

```text
Q-Learning / DQN：学动作价值 Q(s, a)，大模型后训练中较少直接使用
Actor-Critic：策略模型负责生成，价值模型负责估计好坏
PPO：Actor-Critic 路线中的经典策略优化方法
RLHF：把 PPO 用到人类偏好对齐上的训练框架
DPO：从偏好优化目标出发，绕开在线 RL 和显式奖励模型
GRPO：PPO 类方法在大模型推理训练中的简化变体
RLVR：用可验证 reward 训练模型，常和 GRPO 组合
```

### 22.8 DPO 专题：直接偏好优化

前面的第 22.7 节已经用 DPO、PPO/RLHF、GRPO/RLVR 的对比建立了整体认识。本节进一步把 DPO 单独展开，重点回答：

```text
DPO 为什么不需要显式 Reward Model？
偏好数据怎么准备？
Policy Model 和 Reference Model 怎么初始化？
DPO loss 怎么推动 chosen 和 rejected 的概率变化？
beta 参数怎么调？
```

> 本节主要参考 DPO 原论文：Rafailov et al., [Direct Preference Optimization: Your Language Model is Secretly a Reward Model](https://arxiv.org/abs/2305.18290)，并参考 [Hugging Face TRL DPOTrainer 文档](https://huggingface.co/docs/trl/dpo_trainer) 的工程接口。

#### 22.8.1 DPO 的核心思想

DPO 的提出背景是：标准 PPO-RLHF 训练链路比较重。

```text
偏好数据
-> 训练 Reward Model
-> 在线 rollout
-> Reward Model 打分
-> Value Model 估计 advantage
-> PPO 更新策略
```

这条链路通常需要同时维护 Policy Model、Reference Model、Reward Model 和 Value Model。DPO 的意义是：把带 KL 约束的偏好优化目标改写成一个直接作用于偏好数据的分类损失。

```text
偏好数据
-> Policy Model 和 Reference Model 计算 logprob
-> DPO loss
-> 更新 Policy Model
```

DPO 仍然使用 Reference Model，但不需要显式训练 Reward Model，也不需要 PPO 式在线 rollout 和 Value Model。

DPO 的关键是把奖励模型隐式写进策略模型和参考模型的概率比里。从带 KL 约束的 RL 目标出发，最优策略和奖励之间可以写成：

$$
r(x,y)
=
\beta
\log
\frac{
\pi^*(y \mid x)
}{
\pi_{ref}(y \mid x)
}
+
\beta \log Z(x)
$$

这里：

- $x$：prompt
- $y$：回答
- $\pi^*$：偏好目标下的最优策略
- $\pi_{ref}$：冻结的参考模型，通常是 SFT 模型
- $\beta$：KL 约束强度或温度系数
- $Z(x)$：只和 prompt 有关的归一化项

DPO 用当前策略 $\pi_\theta$ 近似 $\pi^*$，得到隐式奖励：

$$
\hat r_\theta(x,y)
=
\beta
\log
\frac{
\pi_\theta(y \mid x)
}{
\pi_{ref}(y \mid x)
}
+
\beta \log Z(x)
$$

在同一个 prompt 下比较 chosen 和 rejected 时，$\beta \log Z(x)$ 会相互抵消，所以真正影响偏好比较的是：

$$
\hat r_\theta(x,y_w)
-
\hat r_\theta(x,y_l)
=
\beta
\left[
\log
\frac{
\pi_\theta(y_w \mid x)
}{
\pi_{ref}(y_w \mid x)
}
-
\log
\frac{
\pi_\theta(y_l \mid x)
}{
\pi_{ref}(y_l \mid x)
}
\right]
$$

其中 $y_w$ 表示 chosen / winner response，$y_l$ 表示 rejected / loser response。

偏好概率可以用 Bradley-Terry 模型表示：

$$
P(y_w \succ y_l \mid x)
=
\sigma
\left(
\hat r_\theta(x,y_w)
-
\hat r_\theta(x,y_l)
\right)
$$

代入上面的隐式奖励，就得到常见 DPO loss：

$$
\mathcal{L}_{DPO}(\theta)
=
-
\mathbb{E}_{(x,y_w,y_l)}
\left[
\log
\sigma
\left(
\beta
\left[
\log
\frac{
\pi_\theta(y_w \mid x)
}{
\pi_{ref}(y_w \mid x)
}
-
\log
\frac{
\pi_\theta(y_l \mid x)
}{
\pi_{ref}(y_l \mid x)
}
\right]
\right)
\right]
$$

最短理解是：

$$
\hat r_\theta(x,y)
\propto
\beta
\log
\frac{
\pi_\theta(y \mid x)
}{
\pi_{ref}(y \mid x)
}
$$

也就是说，DPO 把当前策略相对参考策略更愿意生成某个回答的程度，看成这个回答的隐式奖励。

#### 22.8.2 偏好数据集的构建

DPO 的核心训练样本是：

```text
prompt
+ chosen response
+ rejected response
```

对于同一个 prompt，chosen 应该明显优于 rejected。这个偏好可以来自人工标注、AI 评审、线上反馈、规则检查，或者多个来源的组合。

一个常见构建流程是：

```text
收集 prompt
  |
  v
为每个 prompt 准备多个候选回答
  |
  v
人工 / AI / 规则比较回答质量
  |
  v
选出 chosen 和 rejected
  |
  v
清洗偏好对
  |
  v
封装成 DPO 训练样本
```

Prompt 的来源可以包括：

- 真实用户问题脱敏后的样本
- 人工编写的典型任务
- SFT 数据中的指令
- 对薄弱能力、长尾问题和安全边界的专项补充

偏好对清洗时，应重点检查：

- chosen 和 rejected 是否真的回答了同一个 prompt
- chosen 是否明显优于 rejected，而不是差异极弱或标注冲突
- 是否包含隐私、脏数据、乱码、截断回答和模板污染
- 回答长度是否存在明显偏差，避免模型把“更长”错误学成“更好”
- 数据是否覆盖目标场景，而不是只集中在少量问题类型

一种简化 JSON 数据格式是：

```json
{
  "prompt": "请解释什么是 KL 散度。",
  "chosen": "KL 散度用于衡量两个概率分布的差异，但它通常不对称。",
  "rejected": "KL 散度就是两个数字相减。"
}
```

如果是多轮对话，可以把 prompt 和回答分别封装为消息列表。不同训练框架的字段名可能不同，使用时需要以对应框架文档为准。

#### 22.8.3 图解 DPO 的实现与训练

DPO 常见初始化方式是：

```text
SFT Model
  |
  +--> Policy Model：可训练
  |
  +--> Reference Model：冻结
```

Policy Model 是最终要得到的模型。Reference Model 通常是同一个 SFT 模型的冻结副本，用来提供偏移基准。

DPO 训练全景图：

```text
(prompt, chosen, rejected)
  |
  +--> Policy Model
  |      |
  |      +--> log pi_theta(chosen | prompt)
  |      |
  |      +--> log pi_theta(rejected | prompt)
  |
  +--> Reference Model（冻结）
         |
         +--> log pi_ref(chosen | prompt)
         |
         +--> log pi_ref(rejected | prompt)
  |
  v
计算 chosen / rejected 的相对 logprob 差异
  |
  v
DPO loss
  |
  v
只更新 Policy Model
```

训练时通常只统计 response 部分的 log probability，不把 prompt token 本身算进偏好优化目标。

使用 Hugging Face TRL 时，最小代码可以写成：

```python
from datasets import load_dataset
from trl import DPOConfig, DPOTrainer

dataset = load_dataset("json", data_files="preferences.jsonl", split="train")

training_args = DPOConfig(
    output_dir="outputs/dpo-model",
    beta=0.1,
)

trainer = DPOTrainer(
    model="your-sft-model",
    ref_model="your-sft-model",
    args=training_args,
    train_dataset=dataset,
)

trainer.train()
```

这段代码表达的是最小训练结构，不是完整生产配置。真实训练通常还需要设置 batch size、learning rate、最大序列长度、梯度累积、评估集、日志和检查点策略。

#### 22.8.4 DPO 实践经验

`beta` 控制偏好优化强度和参考模型约束之间的平衡。

```text
beta 较小：
    对偏好差异更敏感
    策略更容易偏离 Reference Model

beta 较大：
    Reference Model 约束更强
    策略更新更保守
```

需要注意，不同实现对 `beta` 的解释和默认值可能有差异。实践中不要只看训练 loss，还要结合验证集偏好胜率、KL、输出长度、拒答率、安全指标和人工样例评估。

DPO 对模型能力的影响通常取决于数据分布：

| 数据特点 | 可能影响 |
|---|---|
| chosen 长期比 rejected 更长 | 模型可能学会偏好冗长回答 |
| 安全拒答样本比例过高 | 模型可能过度拒答 |
| 风格类偏好过于单一 | 输出可能模式化 |
| 偏好标注质量高且覆盖充分 | 目标场景中的回答质量更稳定 |
| 数据只覆盖少数任务 | 未覆盖能力可能没有改善，甚至出现退化 |

因此，DPO 训练不能只关注 loss 下降。需要对帮助性、正确性、安全性、长度、风格和原有通用能力做多维评估。

#### 22.8.5 DPO 进阶

DPO 和 PPO-RLHF 的核心区别如下：

| 对比项 | PPO-RLHF | DPO |
|---|---|---|
| 偏好信号 | 先训练 Reward Model，再输出标量 reward | 直接使用 chosen / rejected 偏好对 |
| 在线 rollout | 通常需要 | 不需要 PPO 式在线 rollout |
| Reward Model | 通常需要 | 不需要显式 Reward Model |
| Value Model | 通常需要 | 不需要 |
| Reference Model | 通常需要，用于 KL 惩罚 | 通常需要，用于构造相对 logprob |
| 训练复杂度 | 高，多模型联动 | 较低，更接近监督式训练 |
| 探索新回答 | 可以通过在线采样持续探索 | 主要受离线偏好数据覆盖范围限制 |

DPO 梯度的直觉可以这样理解：

```text
如果模型还没有明显偏向 chosen：
    梯度较强
    -> 提高 chosen 的相对概率
    -> 降低 rejected 的相对概率

如果模型已经明显偏向 chosen：
    梯度减弱
    -> 避免继续过度推动这个样本
```

可以定义偏好 margin：

$$
m_\theta
=
\beta
\left[
\log
\frac{
\pi_\theta(y_w \mid x)
}{
\pi_{ref}(y_w \mid x)
}
-
\log
\frac{
\pi_\theta(y_l \mid x)
}{
\pi_{ref}(y_l \mid x)
}
\right]
$$

DPO loss 可以写成：

$$
\mathcal{L}_{DPO}
=
-
\log \sigma(m_\theta)
$$

对 margin 求导：

$$
\frac{
\partial \mathcal{L}_{DPO}
}{
\partial m_\theta
}
=
-
\sigma(-m_\theta)
$$

当 $m_\theta$ 较小时，$\sigma(-m_\theta)$ 较大，更新信号较强；当模型已经明显偏好 chosen、$m_\theta$ 较大时，更新信号自然减弱。

到这里，大模型相关的强化学习主线已经完成：

```text
基础篇 Actor-Critic
-> 策略优化算法
-> 大模型 RL 映射
-> RLHF / RLAIF / DPO / GRPO / RLVR
```

## 23. 一条实用的学习路线

如果你准备继续深入，建议按下面顺序学习：

1. 先区分 Bandit 和 MDP，再理解回报、价值函数、贝尔曼方程
2. 再掌握 DP、MC、TD 三类价值估计方法
3. 然后学习 SARSA、Q-Learning 和 TD Learning 的更新逻辑
4. 接着理解深度强化学习如何用神经网络近似 $V$、$Q$ 和 $\pi$
5. 再学习 Policy Gradient 和 REINFORCE
6. 然后进入 Actor-Critic、A2C、SAC、GAE、PPO、DPG/DDPG/TD3
7. 再补 MARL、模仿学习、Offline RL/OPE、Model-Based、HRL、Distributional RL 等扩展主题
8. 然后学习奖励设计、安全约束和 Reward Hacking，避免只会套算法但不会建模
9. 回到应用场景，练习把真实问题拆成状态、动作、奖励、约束、数据来源和算法选择
10. 最后结合大模型 RL、RLHF、RLAIF、DPO、GRPO/RLVR 理解大模型训练中的强化学习思想

## 24. 总结

强化学习的核心不是“拟合答案”，而是“在交互中学会决策”。

基础篇建立的是第一条主线：

- 用 MDP 建模问题
- 用回报定义长期目标
- 用价值函数估计未来收益
- 用 Q-Learning 学值
- 用 Policy Gradient 直接学策略
- 用 Actor-Critic 把两条路线结合起来

扩展篇在这条主线之上补了三层内容：

- **策略优化层**：A2C、SAC、GAE、PPO、DPG/DDPG/TD3 解决“策略模型怎么稳定更新”
- **大模型训练层**：RLHF、RLAIF、DPO、GRPO/RLVR 说明强化学习思想如何进入偏好对齐和推理训练
- **问题扩展层**：MARL、模仿学习、Offline RL/OPE、Model-Based RL、HRL、Distributional RL 分别处理多智能体、奖励难设计、只能使用历史日志、样本昂贵、长时序和风险分布问题
- **工程建模层**：奖励设计、安全约束和 Reward Hacking 处理“目标是否写对、底线是否守住、指标是否被钻空子”的问题

最后回到应用时，最重要的不是背算法名，而是判断问题结构：

```text
这是序列决策吗？
状态、动作、奖励能定义清楚吗？
哪些行为是硬约束，不能被高 reward 抵消？
训练数据来自在线交互还是历史日志？
探索成本能不能承受？
是否需要多个智能体协作或竞争？
```

能回答这些问题，才算真正把强化学习从概念学到了工程建模。
