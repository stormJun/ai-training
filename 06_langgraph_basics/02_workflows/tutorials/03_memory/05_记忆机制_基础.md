# 记忆机制基础

这一节我们先看一个最小的长期记忆示例。

目标很明确：

- 用 LangGraph 处理对话
- 用 Redis 把对话内容按 `thread_id` 持久化
- 让不同用户在不同会话里拥有各自独立的历史记忆

---

## 先理解短期记忆和长期记忆

在 Agent 系统里，“记忆”通常分成两类：

- 短期记忆
  只在当前会话里生效，随着图执行不断更新
- 长期记忆
  可以跨会话、跨线程保存，后续还能被再次取回

这一节的重点是第二类，也就是长期记忆。

---

## 这个示例做了什么

示例本质上是一个简单聊天图：

```text
START -> chat -> END
```

但这个 `chat` 节点在调用模型前，会先做两件事：

1. 读取当前 `thread_id` 对应的历史记忆
2. 把当前用户消息也写进长期记忆

模型生成回复后，又会把 AI 回复写回 Redis。

所以这个示例想说明的是：

> 即使图结构很简单，只要把“记忆读写”放进节点里，就能得到跨轮次、跨线程的长期记忆能力。

---

## 状态结构

这里的状态只有一个字段：

```python
class GraphState(TypedDict):
    messages: Annotated[list[AnyMessage], add_messages]
```

它表示：

- 图里的输入和输出都围绕 `messages`
- 新消息追加到已有消息列表，而不是覆盖旧消息

也就是说，LangGraph 图本身负责“当前轮次的消息流转”，而 Redis 负责“跨会话的长期保存”。

---

## 长期记忆类在做什么

示例里的 `LongTermMemory` 类只是对 Redis 做了一层很薄的封装，主要提供 3 个能力：

- `save_memory(...)`
  把用户消息或 AI 消息写进 Redis
- `get_memory(...)`
  从 Redis 中取出最近若干条历史记录
- `clear_memory(...)`
  删除某个会话的长期记忆

保存时，代码会把数据写成：

```python
{
    "type": "human" | "ai",
    "content": "消息内容"
}
```

读取时，再把它恢复成 `HumanMessage` 或 `AIMessage`，这样就能继续喂给 LangGraph / LangChain 模型。

---

## `chat_node` 是关键

整个示例最值得看的地方就是 `chat_node`：

1. 根据当前 `thread_id` 创建对应的长期记忆实例
2. 把本轮用户输入存进 Redis
3. 取回该会话过去的历史消息
4. 把历史消息和当前消息拼成上下文
5. 调用模型生成回复
6. 再把 AI 回复写回 Redis

这说明：

> 长期记忆不一定是 LangGraph 的单独特性，也可以通过“节点内部显式读写外部存储”来实现。

---

## 这个例子怎么区分不同用户

示例通过 `thread_id` 来做隔离。

比如：

- `alice`
- `bob`

它们各自的消息会写进不同的 Redis key：

```text
memory:alice
memory:bob
```

所以：

- Alice 的偏好不会污染 Bob
- Bob 的对话历史也不会混到 Alice 的上下文里

这就是多用户长期记忆最基础的隔离方式。

---

## 这份示例真正要学的点

- 长期记忆通常要落到外部存储，例如 Redis
- `thread_id` 是隔离不同会话记忆的关键
- LangGraph 图可以很简单，但节点内部可以接入复杂的记忆读写逻辑
- 长期记忆本质上是“历史上下文的持久化与再注入”
